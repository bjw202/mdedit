## 1. 목표와 비목표

### 목표

- 마크다운 편집 중 발생하는 3가지 마찰을 AI로 해소한다:
  1. **고치고 싶은데 손이 많이 가는 문장** → 인라인 편집
  2. **글이 막혀서 진도가 안 나감** → 이어쓰기 (M1에서는 "빈 섹션 채우기"부터)
  3. **문서에 대해 물어보고 싶음** → 문서 대화
- **MVP는 로컬에 설치된 Claude Code headless CLI(`claude -p`)만 사용한다.** 앱은 API 키를 다루지 않는다. (codex 지원은 검증 후 후속 — §8, M4)

### 타깃 사용자 (0.3 재정의)

**1차 타깃: claude CLI를 이미 쓰거나 설치할 수 있는 마크다운 사용자** — 개발자, 기술문서 작성자, 개발조직의 PM/기획자, 마크다운 파워유저. **주 사용 환경은 Windows**이며 macOS를 병행 지원한다(§2 단축키 규칙).

근거(시뮬레이션 ⑤·④): CLI 설치·로그인은 순수 비전문가가 통과할 수 없는 관문이다. 이를 "결함"이 아니라 **타깃 필터**로 인정한다. 다만 이 타깃 안에서도 도구 숙련도는 다양하므로(개발자 ~ 개발조직의 비개발 직군), **단순한 인터랙션 원칙(P1', P4, P5)은 유지**한다.

포지셔닝(정직성 원칙): "로컬 CLI = 프라이버시"라는 암시는 쓰지 않는다 — 프롬프트(문서 일부)는 CLI를 통해 클라우드로 전송된다. 정확한 가치는 **"웹 AI가 차단됐지만 CLI는 승인된 조직에서 AI를 붙일 수 있는 마크다운 에디터"** + **"문단→다이어그램 원스톱"**이다.

### 킬러 유스케이스 (0.3 확정)

**절차 서술 문단 → mermaid 다이어그램 → 프리뷰 즉시 렌더** (시나리오 C). 다듬기는 웹 AI로도 가능한 "느림→빠름" 개선이지만, mermaid 변환은 "불가능→가능"이며 앱의 기존 mermaid 투자(다크 테마, 렌더 파이프라인)와 직접 시너지가 난다. 온보딩·첫 실행 예시·홍보의 대표 시나리오로 사용한다.

### 비목표 (MVP에서 의도적으로 제외)

| 제외 항목 | 이유 |
|---|---|
| **codex CLI 지원 (0.4)** | claude 단독으로 먼저 검증. codex는 무스트리밍·12초 지연으로 별도 UX 분기가 필요(부록 A.2) — 어댑터 인터페이스만 유지하고 M4에서 도입 판단 |
| **번역 프리셋 (0.4)** | 사용 빈도 대비 방향 선택 UX 복잡도(한/영 혼용 감지 오판)가 큼. 필요 시 "직접 입력"으로 커버 |
| 프리셋 커스터마이즈 | 옵션이 많을수록 안 씀. 고정 5개로 시작 |
| 자동완성 자동 트리거 (커서급) | **구조적으로 불가**: CLI 요청당 첫 응답 2.3초 + 입력 12~18K 고정 오버헤드(부록 A) — 키 입력마다 호출하는 커서급 자동완성은 지연·토큰 양쪽에서 성립하지 않음. 항상 수동 호출(버튼/단축키). 힌트 표시는 토큰 0의 로컬 판정(§5.2) |
| 볼트 전역 검색/리서치 | 토큰 비용 큼. 후속 버전 |
| 웹 리서치 | CLI 옵션·권한이 프로바이더마다 달라 MVP 복잡도 증가 |
| 프론트매터 자동 갱신 | 기존 포맷터-frontmatter 충돌 이력 있음 |
| 대화 기록 **영구** 저장 | 저장은 개인정보·용량 이슈만 만듦. 단 세션 내 문서별 대화 캐시는 유지(§6.2) — "영구 저장 안 함"과 "세션 내 유지"는 분리 |

## 2. 설계 원칙 (제약 → 결정)

| # | 제약 | 설계 결정 |
|---|---|---|
| P1' | 타깃 내 숙련도 다양 | 기본은 "제안 카드" 단일 패턴. **diff 뷰는 기본 금지 유지하되, 표·3문장 이상 제안에서 "바뀐 부분만 옅은 배경색" 최소 변경 강조**를 켠다 (기호 +/- 없음) |
| P2 | 회사 환경, 토큰 제한 | 기능별 컨텍스트 상한 고정(§7). 출력도 "결과만, 설명 금지"로 절약 |
| P3 | 프로바이더 확장 가능성 | `AiProvider` trait 어댑터 구조 유지. **MVP 구현은 claude 어댑터 하나** — codex는 인터페이스 계약만 유지(M4) |
| P4 | 복잡하면 안 쓰느니만 못함 | 진입점 딱 2개: 선택 시 ✨ 버튼, 우측 AI 패널(기본 닫힘). 그 외 UI 없음. 축 2 힌트도 **클릭 가능한 버튼**으로 (키보드 전용 진입 금지) |
| P5 | 실수해도 무섭지 않아야 함 | 모든 AI 적용은 CodeMirror 트랜잭션 1개 → Undo(Mod+Z) 한 번에 복원. **변경 위치·범위는 카드에서 본 것과 정확히 일치**해야 한다(§9 무손상 원칙 확장) |
| P6 | 응답이 수 초 걸림 | 전 기능 스트리밍 표시 + 항상 보이는 취소(Esc/버튼). UI 블로킹 금지 |
| P7 | 조용한 실패 금지 | AI 요청·제안 카드가 사라질 때는 반드시 이유를 명시한 배너/카드로 알린다. 무통보 자동 취소 금지. 침묵 절단 금지(§7)의 일반화 |

**인터랙션 통일 규칙**: AI가 텍스트를 제안하는 모든 상황은 동일한 "제안 카드" 컴포넌트를 사용한다. 사용자는 패턴을 한 번만 배우면 된다.

**단축키 플랫폼 규칙 (0.4 신설)**: 모든 단축키는 **Mod 키**로 정의한다 — macOS는 ⌘(Cmd), Windows·Linux는 Ctrl. 본 문서의 `Mod+Enter`, `Mod+Z` 표기는 플랫폼별로 자동 매핑되며, UI 힌트·툴팁·설정 화면의 단축키 표기도 실행 중인 OS에 맞춰 표시한다(⌘⏎ ↔ Ctrl+Enter). 주 사용자가 Windows이므로 **모든 단축키는 Windows에서 우선 검증**한다 (CodeMirror keymap은 `Mod-` 접두어로 정의).

## 3. 전체 아키텍처

```
┌────────────────────────── Frontend (React) ──────────────────────────┐
│                                                                       │
│  CodeMirror 6                          AI 패널 (우측 토글, 기본 닫힘)   │
│  ├── SelectionToolbar  (✨ 버튼)        ├── 채팅 뷰                     │
│  ├── SuggestionCard    (제안 카드 위젯)  ├── 질문 칩 3개                 │
│  └── GhostText         (이어쓰기 표시)   └── 프로바이더 뱃지              │
│           │                                    │                      │
│           └────────── aiStore (zustand) ───────┘                      │
│                • 요청 상태 (idle/streaming/done/error)                 │
│                • 스트림 버퍼, 취소 핸들                                  │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ invoke("ai_request") / listen("ai://chunk")
┌───────────────────────────────┴───────────────────────────────────────┐
│                        Backend (Rust / Tauri)                          │
│                                                                        │
│  src-tauri/src/ai/                                                     │
│  ├── mod.rs         커맨드: ai_request, ai_cancel, ai_detect_providers │
│  ├── provider.rs    trait AiProvider { spawn(prompt) -> ChildStream }  │
│  ├── claude_cli.rs  claude -p <prompt> --output-format stream-json    │
│  ├── detect.rs      which claude → { installed, version, logged_in }  │
│  └── prompt.rs      기능별 프롬프트 템플릿 + 컨텍스트 조립·상한 절단        │
│                                                                        │
│  (codex_cli.rs 는 M4에서 추가 — trait 계약은 지금 확정)                   │
└────────────────────────────────────────────────────────────────────────┘
```

- **요청 = 프로세스 1개.** 요청마다 CLI 프로세스를 스폰하고 stdout을 Tauri 이벤트(`ai://chunk`, `ai://done`, `ai://error`)로 릴레이. 취소 = 프로세스 kill. 세션/상태 관리가 없어 단순하고 견고하다.
- **동시 요청은 1개로 제한.** 진행 중(in-flight) 새 요청 시 기존 요청을 자동 취소하되, **P7에 따라 취소된 쪽에 "새 요청으로 취소되었어요" 표시를 남긴다.**
- **"동시 1개"의 취소 대상은 in-flight 요청뿐이다. 완료되어 검토 대기 중인 제안 카드는 취소 대상이 아니며, 새 요청과 무관하게 유지된다.** 카드가 사라지는 경우는 사용자의 [✕ 취소]·적용, 또는 원문 범위 침범(§4.3) 시 명시 배너와 함께일 때뿐이다.
- 프롬프트 조립은 전부 Rust 쪽 `prompt.rs`에서 — 프론트는 "기능 종류 + 텍스트 조각"만 넘긴다.

## 4. 축 1 — 인라인 편집

### 4.1 UI 구성

**진입**: 텍스트를 선택하면 선택 영역 끝에 ✨ 버튼 하나가 뜬다 (Notion 방식). 우클릭 컨텍스트 메뉴에도 "✨ AI로 편집" 항목을 중복 노출한다(발견성).

**메뉴 (프리셋 5개 고정 + 직접 입력)** — 0.4: 번역 제거, "개요로 정리" 신설:

```
   ┌──────────────────────┐
   │ 🖊  다듬기            │  ← 맞춤법·문장 자연스럽게
   │ 📋  개요로 정리        │  ← 불레틴·개괄식 (주간보고 스타일)
   │ 📊  표로 만들기        │
   │ 🧜  다이어그램으로     │  ← mermaid 코드블록 생성
   │ ✂️  짧게 줄이기        │
   │ ──────────────────── │
   │ ✏️  직접 입력...      │  ← 한 줄 입력창으로 전환
   └──────────────────────┘
```

- **"개요로 정리" (0.4 신설)**: 서술형 문단·산발적 메모를 **개괄식 불레틴**(핵심 항목 · 들여쓰기 계층 · 명사형 종결)으로 변환. 주간보고·회의록·업무 공유 등 최빈 사무 작업을 프리셋으로 흡수 (시뮬레이션 ①D7 "정리하기 부재" 지적과 정합). 원문 성격이 이미 개조식이면 계층·표현만 다듬는다.
- 번역이 필요하면 "직접 입력..."으로 처리 ("영어로 번역해줘"). 프리셋에서 제외한 이유: 사용 빈도 대비 방향 선택(한/영 혼용 감지 오판) UX 비용이 큼 (0.4).
- "직접 입력..." 전환 후 **Esc 또는 ← 버튼으로 프리셋 메뉴로 복귀**할 수 있다.

### 4.2 동작 시나리오 (스토리보드)

   (3문장 이상·표 제안은 바뀐 부분만 옅은 배경색 강조, P1')

[4] "✓ 바꾸기" 클릭 → 원문이 제안으로 교체, 카드 사라짐
    실수했다면? → Mod+Z 한 번에 원문 복원 (트랜잭션 1개)

### 4.3 구현 메모

- ✨ 버튼·제안 카드는 CodeMirror `Decoration.widget` (block widget)으로 구현 — 문서 텍스트를 오염시키지 않고 뷰 레이어에만 존재.
- 제안 적용은 `dispatch({ changes })` 단일 트랜잭션 → undo 1회 복원 보장. 단 P5의 "한 번에 복원"은 적용 직후에만 성립 — 적용 후 타이핑하면 Mod+Z는 타이핑부터 되돌린다(정상 undo 스택 동작, 별도 처리 없음).
- **적용 dispatch 직전에 대상 범위의 현재 텍스트가 카드 생성 시점의 원문과 일치하는지 재검증한다.** anchor가 추적하더라도 원문 앞쪽 편집으로 오프셋이 이동했을 수 있음 — 불일치 시 적용을 중단하고 "원문이 바뀌어 적용할 수 없어요" 카드 표시.
- 선택 영역이 문장 중간에서 끊기면 **교체 범위를 문장 경계까지 자동 확장할지 카드에서 미리 보여준다**: 확장된 범위를 옅게 하이라이트하고 "문장 끝까지 함께 바꿉니다" 라벨 표시 (잘린 어미에 완결 문장이 들어가 "…되었다.다." 충돌 방지). 컨텍스트에는 기존대로 문단 경계까지 포함.
- **스트리밍 중 사용자가 원문 범위를 편집하면 (P7)**: 무통보 취소 대신 카드 자리에 명시 배너 — "원문이 편집되어 이 제안을 멈췄어요 [무시] [다시 요청]". 원문 범위 밖 편집은 요청에 영향 없음(anchor 추적 유지).

### 4.4 선택 길이 가드

§7의 상한을 **두 가지로 분리 정의**한다:

1. **컨텍스트 상한**: CLI에 보내는 주변 맥락의 크기 제한 (기존 §7).
2. **교체 대상 상한**: "바꾸기"로 교체될 선택 텍스트 자체의 크기 제한. **인라인 편집의 선택 텍스트는 절대 절단하지 않는다** — 절단된 결과로 선택 전체를 교체하면 무손실 삭제가 발생하기 때문.

동작 규칙:
- 선택 ≤ 2,000자: 현행대로 처리.
- 선택 > 2,000자: **✨ 메뉴에서 편집 프리셋을 비활성화**하고 안내 표시 — "선택이 너무 길어요. 문단 단위로 나눠 선택해주세요." (침묵 처리 금지, P7)
- 예외: "짧게 줄이기"·"개요로 정리"·"표로 만들기" 등 요약·변환 계열은 4,000자까지 허용하되, 결과는 "아래에 삽입"만 가능("바꾸기" 비활성) — 원문 파괴 경로 차단.

    ※ 힌트 표시는 순수 로컬 판정(커서 위치 계산)이며 AI 요청이 아님 — 토큰 소모 0 (§5.2)

### 5.2 구현 메모 — 힌트와 요청의 분리 (0.4 명확화)

**힌트 ≠ 요청. 힌트는 토큰을 전혀 쓰지 않는다.**

- "3초 멈춤 감지 → 힌트 표시"는 에디터 내부의 커서 위치·타이머 계산만으로 동작하는 **순수 프론트엔드 로컬 로직**이다. CLI 스폰도, 네트워크 호출도, 토큰 소모도 없다.
- AI 요청(= CLI 프로세스 스폰 = 토큰 소모)은 오직 사용자가 **힌트 버튼을 클릭하거나 Mod+Enter를 누른 순간**에만 발생한다. 요청당 비용은 부록 A 기준 1건 $0.0078 수준.
- "커서(Cursor)급" 키 입력 연동 자동완성은 별개 문제다: 키 입력마다 요청이 나가야 하는데 CLI는 요청당 첫 응답 2.3초 + 프로세스 스폰 오버헤드 + 입력 12~18K 고정 토큰이 들어 **지연·비용 양쪽에서 성립하지 않는다**. 이것이 §1 비목표("자동 트리거 제외")의 기술적 근거다. 커서급 경험이 필요해지면 CLI가 아니라 상주 세션/저지연 API 전제의 별도 설계가 필요하다 (후속 검토 과제, MVP 범위 아님).

기타:
- 고스트 텍스트는 CodeMirror 데코레이션(inline widget) — 문서 상태에 없는 순수 뷰 요소.
- "문서 끝" 판정: 마지막 비어있지 않은 줄 이후, 또는 빈 헤딩 아래.

## 6. 축 3 — 문서 대화 (AI 패널)

### 6.0 패널 설계 요구사항 (0.4 신설)

1. **기본 닫힘, 필요할 때만 토글.** 앱 시작 시 패널은 항상 닫혀 있다. 툴바 ✨ 아이콘 또는 단축키로 열고, 닫으면 화면은 기존 3-패널(탐색기/에디터/프리뷰) 레이아웃으로 완전 복귀한다. 패널이 열려 있어도 에디터·프리뷰 동작에 어떤 간섭도 없어야 한다.
2. **기존 디자인 시스템 승계.** 패널의 색·타이포·간격·아이콘·다크/라이트 테마는 앱의 기존 토큰을 그대로 사용한다. 새로운 시각 언어(별도 색상, 별도 폰트, 채팅 앱풍 말풍선 과장)를 도입하지 않는다 — "에디터의 한 패널"이지 "내장된 챗봇 앱"이 아니다.
3. **직관성과 견고성 우선.** 대화는 상태가 많은(스트리밍·적용 카드·재동기화·문서 전환) 복잡 동작이므로:
   - 패널의 모든 상태는 aiStore 단일 소스에서 파생 — UI에 지역 상태 숨김 금지.
   - 어떤 상태(스트리밍 중, 오류, 문서 전환)에서 패널을 닫아도 안전해야 한다: 진행 중 요청은 취소되고(P7 표시), 대화 캐시는 유지.
   - 각 인터랙션 요소(칩·입력창·적용 카드)는 항상 1개의 명확한 다음 행동만 제시한다.

### 6.2 동작 시나리오

**시나리오 G: 문서에 대해 질문**

```

```

**문서-대화 동기화 (stale context 방지)**:
- 첫 질문 이후 사용자가 문서를 편집하면, 다음 후속 질문 전송 시 패널에 재동기화 칩을 표시한다 — "문서가 수정되었어요 [🔄 다시 읽고 답하기]".
- 사용자가 칩을 누르면 해당 질문은 "첫 질문" 규칙(문서 재전송)으로 처리. 누르지 않으면 이력만으로 답하되, 답변 상단에 "수정 전 문서 기준" 배지를 붙인다 (P7 — AI가 옛 문서를 보고 답하는 상황을 침묵시키지 않음).

**시나리오 H: 답변 속 수정 제안 → 카드로 적용 (위치 확정 상호작용)**

```
🤖 답변에 수정 제안 블록이 포함되면:
   ┌─ 🤖 ────────────────────────────────┐
   │ 결론 첫 문장을 이렇게 고치는 게        │
   │ 좋겠습니다:                          │
   │ ┌─ ✨ 제안 ─────────────────────┐    │
   │ │ 매출은 전분기 대비 5% 증가했다. │    │
   │ │   [✓ 문서에 적용]  [✕ 무시]   │    │ ← 축 1과 동일한 카드
   │ └───────────────────────────────┘    │
   └─────────────────────────────────────┘
```

**적용 위치 확정 절차** — AI 응답에 원문 인용을 포함하도록 프롬프트로 강제한 뒤:

1. **단일 exact match** → 해당 위치로 스크롤 + 대상 텍스트 하이라이트 + 에디터 인라인 확인 카드 "여기를 바꿀까요? [✓ 바꾸기] [✕]". **자동 즉시 교체 금지** — 사용자가 위치를 눈으로 확인한 뒤에만 적용.
2. **다중 match** → 모든 후보를 하이라이트하고 첫 후보로 스크롤, "N곳에서 발견 — 바꿀 곳을 클릭하세요" 안내. 첫 번째를 임의 선택하지 않음 (엉뚱한 위치 파괴 방지).
3. **match 실패** → fuzzy 최근접 후보(문장 단위 유사도)가 있으면 그 위치를 하이라이트하고 "비슷한 문장을 찾았어요 — 여기를 바꿀까요?" 확인. 그마저 없으면 "문서에서 해당 문장을 찾지 못했어요. 제안을 복사해 직접 붙여넣을 수 있어요 [📋 복사]".

- 대화는 **세션 내 문서별 캐시**: 다른 문서로 전환해도 세션 중에는 각 문서의 대화가 유지되고, 되돌아오면 이어서 보인다. 앱 종료 시 소멸(영구 저장 없음 — §1 비목표 유지). 패널 상단에 "ⓘ 이 대화는 앱을 닫으면 사라져요" 상시 표기.
- 다른 문서로 전환하면 패널 상단에 "○○.md와의 대화" 라벨로 현재 컨텍스트를 명시.

## 7. 토큰 절약 전략 (컴팩트 컨텍스트)

| 기능 | 컨텍스트 구성 | 컨텍스트 상한 | 교체 대상 상한 |
|---|---|---|---|
| 인라인 편집 | 선택 영역 + 앞뒤 각 1문단 | ~2K자 | 선택 2K자 (초과 시 §4.4 가드, 절단 금지) |
| 이어쓰기/섹션 채우기 | 헤딩 아웃라인 전체 + 커서 앞 본문 꼬리 (+문체 지시) | 아웃라인 무제한(짧음) + 본문 1.5K자 | 해당 없음 (삽입만) |

| 문서 대화(후속) | 이전 Q&A 이력만 (최근 6턴) | 이력 자체 | 해당 없음 |

- 시스템 프롬프트는 기능당 2~3문장 고정 문자열. 공통 지시: **"결과 텍스트만 출력. 설명·인사·마크다운 펜스(요청한 경우 제외) 금지."** → 출력 토큰 절약 + 후처리 단순화.
- 절단이 발생하면 UI에 **구체 범위를 명시**해 표시: "문서 앞부분과 끝부분만 참고했어요 (중간 약 N자 제외)". 침묵 절단 금지.
- 상태바에 세션 요청 횟수 노출("✨ 12회"). 툴팁에 "요청당 비용은 대체로 균일해요 · 기본 모델(haiku) 사용 중" 보조 문구 — 카운터에 기준점 제공. 토큰 수치 같은 개발자 지표는 숨긴다.

## 8. 프로바이더 어댑터

### 8.1 인터페이스 (trait는 확정, MVP 구현은 claude 단독)

```rust
trait AiProvider {
    fn id(&self) -> &str;                      // "claude" (M4: "codex")
    fn detect(&self) -> ProviderStatus;         // installed? version? logged_in?
    fn spawn(&self, prompt: &str) -> Result<ChildStream>;  // 스트리밍 핸들
    fn capabilities(&self) -> Capabilities;     // supports_streaming, typical_latency
}
```

**0.4 결정: MVP는 Claude Code 어댑터만 구현·출시한다.** codex는 (1) 델타 스트리밍 부재로 별도 스피너 UX 분기가 필요하고, (2) 12초 지연이 인라인 편집·이어쓰기의 가치 제안과 충돌하며(시뮬 ④·⑤), (3) 검증 항목을 2배로 만든다. claude 단독으로 M0~M3을 검증한 뒤 **M4에서 codex 도입을 §12 지표로 판단**한다. trait 계약(`capabilities()` 포함)은 지금 확정해 M4 때 어댑터 추가만으로 붙게 한다. codex 실측 결과는 부록 A.2에 보존.

**로그인 상태 선제 감지**: `detect()`는 `--version` 성공 여부(installed)에 더해 **로그인 여부를 실제 호출 전에 판정**한다 — 인증 세션 파일 존재/유효성 확인(claude: `~/.claude` 세션), 판정 불가 시 앱 시작 후 백그라운드 1회 경량 프로브. 미로그인이면 ✨를 숨기지 않고 **"연결 필요" 상태로 표시** — 첫 클릭이 실패 카드가 되는 것을 방지.

**Claude Code 호출 (실측 확정, 부록 A.1)**:

| 항목 | 내용 |
|---|---|
| 호출 | `claude -p <prompt> --system-prompt <sys> --model haiku --output-format stream-json --include-partial-messages --verbose --setting-sources ""` + env `MAX_THINKING_TOKENS=0` |
| 스트림 | `stream_event` → `content_block_delta` → `text_delta` (토큰 단위 스트리밍) |
| 체감 지연 | 첫 텍스트 ~2.3초, 완료 ~2.7초 (문장 교정 기준) |
| 감지 | `claude --version` + 세션 파일 |
| 인증 | CLI 자체 로그인 세션 사용 |

필수 격리 규칙 (부록 A 참조):

1. **빈 스크래치 디렉토리에서 스폰한다.** 문서 폴더나 프로젝트 폴더에서 실행하면 그 폴더의 CLAUDE.md/훅이 로드된다 (실측: 프로젝트 폴더 실행 시 입력 90K 토큰 + 훅 부작용). 디렉토리 생성 실패(권한·디스크) 시 오류 카드로 처리.
2. **`--setting-sources ""`** 로 사용자·프로젝트 설정을 차단하고, **`MAX_THINKING_TOKENS=0`** 으로 사고 토큰을 끈다 (미차단 시 간단한 교정에도 수 초 사고).
3. 스트리밍 UX: 타이핑되듯 표시. 10초 무소식 → "생각 중이에요..." 에스컬레이션(§9).

### 8.2 설정 UX

```
설정 > AI
┌───────────────────────────────────────────────┐
│ AI 도구                                        │
│  Claude Code        ✅ 사용 가능 (v2.1.x)      │
│                                               │
│  (Codex 등 다른 도구는 추후 지원 예정)            │
│                                               │
│ □ 고급 모델 사용 (sonnet — 더 정확, 더 느림)     │
│ □ AI 기능 끄기                                 │ ← 개인 토글
└───────────────────────────────────────────────┘
```

**상태별 동작**:
- claude 설치·로그인 완료 → 자동 활성화. 단 **1회성 고지 배너**: "Claude로 AI 기능을 사용합니다. 선택한 텍스트와 문서 일부가 처리를 위해 전송됩니다. [확인] [설정]" — 데이터 전송 미고지 방지.
- 설치는 됐으나 미로그인 → ✨ 표시하되 "연결 필요" 상태. 클릭 시 **앱 내 연결 안내 모달**.
- 미설치 → ✨ 버튼 숨김. **AI 패널 토글은 항상 노출**하고, 미설치 시 패널 안에 연결 온보딩을 표시 (발견 경로 확보).

**연결 온보딩**: 미설치/미로그인 사용자를 위한 단계별 위저드 — OS 감지(Windows 우선) → 설치 명령 복사 버튼 → "터미널 여는 법" 스크린샷 1장 → 로그인 안내 → [다시 확인] 버튼으로 자동 재감지. "설치 안내 보기 ↗" 외부 링크 하나로 넘기지 않는다.

**조직 정책**: 환경변수 `MDEDIT_AI_DISABLED=1` 또는 앱 설정 디렉토리의 정책 파일이 존재하면 AI 기능을 강제 비활성화하고 설정 토글을 잠금 표시한다. 조직 배포 시 보안팀이 통제할 수 있는 최소 장치. (감사 로그·MDM 연동은 비목표 — 후속 버전)

## 9. 오류·엣지 케이스 UX

| 상황 | 동작 |
|---|---|
| CLI 미설치 | ✨ 진입점 숨김. AI 패널(항상 노출)에 연결 온보딩 표시 |
| CLI 설치·미로그인 | ✨ "연결 필요" 상태로 표시. 클릭 시 앱 내 연결 안내 모달(위저드) — **"터미널에서 claude 실행" 문구 금지** |
| CLI 로그인 만료 (사용 중 발생) | 카드에 "로그인이 풀렸어요 [연결 안내 보기]" → 온보딩 모달 재사용. 원문 무손상 |
| 오류 원인 분류 | stderr 분류표로 **로그인 만료 / 네트워크 차단 / 기타**를 구분. 네트워크 오류를 로그인 만료로 오안내하지 않음 |
| 오프라인·프록시 차단 | "네트워크에 연결할 수 없어요. 사내 프록시 환경이라면 관리자에게 문의하세요" — 재시도 루프 유도 금지 |
| 응답 지연 | 10초 무소식 → "생각 중이에요..." + 취소 강조. 60초 타임아웃 → 오류 카드 |
| 프로세스 비정상 종료 | "잠시 문제가 있었어요 [다시 시도]" — stderr는 로그 파일에만 |
| 스트림 파싱 실패 (CLI 버전업) | 최종 `result` 필드로 2차 파싱 시도 → 그것도 실패 시 **오류 카드** ("도구 업데이트로 문제가 생겼어요"). **raw JSON을 카드에 노출하지 않음** |
| 스트리밍 중 문서 저장 (Mod+S) | **요청 유지** — 저장은 AI 요청과 독립 (습관성 저장이 결과를 날리는 과잉 결합 제거) |
| 스트리밍 중 문서 전환 | 요청 자동 취소 + 원래 문서로 돌아오면 "문서를 전환해서 요청이 취소됐어요" 1회 표시 (P7) |
| 제안이 빈 문자열/원문과 동일 | "이미 자연스러워서 바꿀 곳이 없어요" 카드 (빈 교체 방지, 문구 귀책 중립화) |
| 요청 연타 | 동시 1개 원칙 — 새 요청이 **in-flight 요청만** 취소(취소 표시 남김). 검토 중 제안 카드는 유지 (§3) |
| 원문 범위 침범 편집 | 무통보 취소 금지 — "원문이 편집되어 제안을 멈췄어요 [무시] [다시 요청]" 배너 (§4.3, P7) |

**공통 원칙**: 어떤 실패도 문서를 건드리지 않는다. 문서 변경은 오직 사용자의 [바꾸기/넣기/적용] 클릭으로만 발생하며, **변경되는 위치와 범위는 사용자가 카드·하이라이트에서 확인한 것과 정확히 일치해야 한다** — exact-match 자동 교체 금지(§6.2), dispatch 직전 원문 재검증(§4.3), 선택 절단 교체 금지(§4.4)가 이 원칙의 구현이다.

## 12. 킬 크라이테리아 (출시 후 실패 판정 지표)

출시 후 아래 지표가 임계를 넘으면 해당 전제가 죽은 것으로 판정하고 방향을 수정한다.

|---|---|---|---|
| AI 활성화율 (CLI 감지 성공/전체 사용자) | < 20% | 진입장벽이 타깃을 죽임 | 온보딩 강화 또는 내장 프로바이더 검토 |

## 부록 A — CLI 실측 결과 (2026-07-16, macOS)

측정 방법: 각 CLI를 빈 디렉토리에서 스폰, stdout 라인별 타임스탬프 기록. 과제: 짧은 한국어 문장 교정.

한계: 본 실측은 (1) macOS 단일 환경, (2) 짧은 문장 단일 과제 기준이다. 2.33초에 프로세스 기동 시간이 포함되는지 분리 측정되지 않았으며, **주 사용 환경인 저사양 Windows + 실시간 백신 환경은 미검증 — M0에서 보완 실측한다** (§11 리스크).

### A.3 설계 반영 요약

1. 스폰 cwd는 앱 전용 빈 스크래치 디렉토리로 고정 (문서 폴더 금지).
2. 어댑터에 `supports_streaming` capability — MVP의 claude는 true(타이핑 UX). false 분기는 M4에서 활성화.
3. 기본 모델: haiku 고정(속도·비용), 설정에 "고급 모델 사용" 토글 + ↻ 3회 소진 시 인라인 sonnet 폴백(§4.2 B).
4. 60초 타임아웃(§9) 유지.
5. 요청당 입력 12~18K의 고정 오버헤드가 있으므로, "토큰 절약"의 실효 레버는 §7의 앱 측 컨텍스트 상한 + 서버 캐시 활용(동일 시스템 프롬프트 유지)이다. 이 고정 오버헤드가 **키 입력 연동 자동 트리거(커서급)가 성립하지 않는 이유**이기도 하다(§5.2).
