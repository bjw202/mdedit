# SPEC-PREVIEW-022 구현 계획

결정이 바뀔 가능성이 큰 것부터 적었다. §D(열린 결정)를 먼저 보라.

## A. 사전 확인 사항 (plan 단계에서 읽은 사실)

- 기준: `main` `cdaadcf`, 브랜치 `WT-html-charset`.
- `src-tauri/src/lib.rs`는 `tauri::Builder`에 URI 스킴을 등록하지 않는다(`register_uri_scheme_protocol`·`register_asynchronous_uri_scheme_protocol` grep 결과 0건, 종료 코드 1). 사용 중인 플러그인 4개(opener, shell, dialog, single-instance)의 소스에도 스킴 등록이 없다(같은 grep, 종료 코드 1). 그래서 지금 asset 출처는 원격으로 분류된다(research.md §3).
- `src-tauri/Cargo.lock`: `tauri` 2.10.3, `source = "registry+https://github.com/rust-lang/crates.io-index"`.
- 레지스트리의 tauri 2.10.3 소스: 143개 파일, 1.6 MB, `LICENSE_MIT`·`LICENSE_APACHE-2.0` 포함.
- `core:default`는 `core:app:default`를 통해 `allow-version`을 허용한다(`tauri-2.10.3/permissions/app/autogenerated/reference.md:7`). 부작용 없는 플러그인 명령 탐침(`plugin:app|version`)으로 쓴다.
- Rust 테스트는 CI에서 돌지 않는다. 명령: `~/.cargo/bin/cargo test --manifest-path src-tauri/Cargo.toml <filter>`.

## B. 접근 방식 (권장안 X 기준)

1. **tauri 패치 방식 (가장 바뀔 수 있는 결정)**: 레지스트리의 `tauri-2.10.3/`을 `src-tauri/vendor/tauri/`에 그대로 복사하고, `src-tauri/Cargo.toml`에 `[patch.crates-io] tauri = { path = "vendor/tauri" }`를 더한다. `Cargo.lock`의 `tauri` 항목은 `source` 줄이 사라진다. 다른 tauri 계열 크레이트(`tauri-build`, `tauri-macros`, `tauri-utils`, `tauri-runtime-wry`)는 그대로 레지스트리에서 받는다. 변형 X2를 고르면 `path` 대신 `git`+`rev`가 되고 vendor 디렉터리는 생기지 않는다.
2. **판정 규칙**: 새 파일 `src-tauri/vendor/tauri/src/protocol/asset/charset.rs`에 순수 함수 `html_content_type(mime: &str, full_body: Option<&[u8]>) -> String`을 둔다(표준 라이브러리만 사용). `asset.rs`에서 `mod charset;`로 쓴다.
3. **핸들러 수정 범위**: `asset.rs`에서 100행의 `CONTENT_TYPE` 설정을 분기별로 나눈다. Range 분기와 HEAD 분기는 지금처럼 `mime_type`을 쓰고, 비Range GET 분기만 본문을 얻은 뒤 `html_content_type(&mime_type, Some(&buf))`로 정한다. 다중 범위 부분 헤더(198-199행)는 그대로 둔다. 그 밖의 줄은 바꾸지 않는다(AC-004 허용 목록).
4. **테스트 배치**: 앱 크레이트 통합 테스트 `src-tauri/tests/asset_charset.rs`가 `#[path = "../vendor/tauri/src/protocol/asset/charset.rs"] mod charset;`로 같은 파일을 불러 단위 표를 검증한다. tauri 크레이트의 개발 의존성 없이 앱의 `cargo test`로 돈다. 같은 파일에 상류 추적 가드(REQ-010)를 둔다: `Cargo.lock`을 읽어 `tauri`가 2.10.3이고 `source` 줄이 없음을 단언한다.
5. **fixture**: `src-tauri/tests/fixtures/charset/` 아래에 두고, 단위 테스트가 `include_bytes!`로 같은 파일을 읽는다(실기기 확인과 단위 표가 같은 바이트를 쓴다). 목록은 acceptance.md § Fixture.
6. **in-page 탐침**: fixture HTML은 ASCII 스크립트로 `document.characterSet`과 `fetch(location.href)`의 응답 `content-type`을 화면에 쓴다. 릴리스 빌드에서 개발자 도구가 없어도 두 OS에서 헤더를 기록할 수 있다. 원본 보기는 스크립트를 허용한다(선명 모드에서는 동작하지 않으며 그래도 된다).

## C. 마일스톤 (순서)

- **M0 — 재현 (코드 변경 전, Windows·macOS 실기기, REQ-011)**
  - fixture를 먼저 만든다(M1의 일부를 당겨 온다. fixture만 만들고 코드는 바꾸지 않는다).
  - 현재 빌드에서 `utf8-no-meta.html`, `euckr-meta.html`을 원본 보기로 연다(macOS는 토글로 원본 보기를 고른다). 화면의 `content-type`, `characterSet`, 한글 표시 상태를 기록하고 화면을 캡처한다. 가능하면 개발 빌드의 개발자 도구(Windows WebView2 DevTools Network, macOS Safari Web Inspector)에서 응답 헤더도 캡처한다.
  - 멈춤 규칙: `content-type`에 이미 charset이 있거나 한글이 깨지지 않으면 구현을 멈추고 차단 보고를 돌려준다. 문서 요청에 Range가 붙어 있으면 그것도 차단 보고 사유다(research.md G-2).
- **M1 — RED**
  - `src-tauri/tests/asset_charset.rs`를 쓴다(단위 표 + 상류 추적 가드). `charset.rs`와 패치가 없으므로 컴파일 실패 또는 가드 실패를 확인하고 출력을 progress.md에 붙인다.
  - fixture 바이트 확인: 커밋 후 `xxd`로 EUC-KR·UTF-16 fixture가 바뀌지 않았는지 본다(research.md R-3).
- **M2 — GREEN**
  - vendor 복사, `[patch.crates-io]`, `charset.rs`, `asset.rs` 수정.
  - `cargo build`, `cargo test --test asset_charset` 통과.
  - `cargo fmt`·`cargo clippy`가 vendor 디렉터리를 건드리지 않는지 확인한다(research.md R-4).
- **M3 — 정적 게이트**: AC-004(상류 diff 허용 목록), AC-005(스킴 등록 0건), AC-006(변경 파일 이름 목록), AC-007(회귀 스위트).
- **M4 — 실기기 확인**: AC-009(수정 확인), AC-010(회귀), AC-011(보안 탐침). macOS는 직접, Windows는 사용자가 확인한다.
- **M5 — 마무리**: `charset.rs`에 `@MX:NOTE`(판정 규칙과 사유), `asset.rs` 수정 줄에 `@MX:WARN`(상류 패치 지점, `@MX:REASON`: tauri 업그레이드 시 research.md §6 절차 필요). 주석 언어는 `code_comments: ko`. `[patch.crates-io]` 위에 한 줄 주석으로 research.md §6 위치를 적는다.

## D. 열린 결정 (run 시작 전 사용자 확인 필요)

1. 패치 전달 방식 — 권장안 X(tauri 소스 1.6 MB·143개 파일을 `src-tauri/vendor/tauri/`에 들여와 `path`로 패치)와 변형 X2(사용자 GitHub 포크를 `git`+`rev`로 패치, 릴리스 CI가 포크를 받을 수 있어야 함) 중 하나를 run 시작 전 구현 승인 때 사용자가 고른다. 기본값은 X다. 두 안은 보안 성질과 바뀌는 코드가 같고, 차이는 저장소 크기와 외부 의존뿐이다. 그래서 요구사항·수용 기준은 어느 쪽이든 그대로이며, X2를 고르면 AC-004의 diff 대상이 vendor 디렉터리 대신 포크의 `rev`가 된다.
2. 안 A(앱 `asset` 스킴 재등록)는 기각으로 확정한다. 근거는 research.md §3이며, 코디네이터 세션이 `tauri-2.10.3/src/webview/mod.rs:1698-1720`(앱이 등록한 스킴을 로컬로 판정)과 `:1769-1775`(로컬이면 `Origin::Local`)를 다시 읽어 확인했다. 사용자가 그래도 안 A를 원하면 이 SPEC을 다시 계획한다.
3. tauri 상류에 "asset 응답에 charset" 이슈·PR을 올릴지. 기본은 이 SPEC 밖이다. 상류가 고치면 §6 절차로 패치를 걷어낸다.
4. macOS 실기기 확인: 기본은 수행(토글로 원본 보기 선택). 생략하면 macOS 판정은 미검증 갭으로 남기고 SPEC은 `implemented`까지만 닫는다.

## E. 위험 관리 요약

- 보안: 권장안 X는 앱의 스킴 등록이 없다는 성질에 기대며, AC-005가 정적으로, AC-011이 실기기로 지킨다.
- 상류 어긋남: REQ-010 가드와 research.md §6 절차.
- 원인 가설: M0 멈춤 규칙.
- 잔여 위험: 들여온 사본에 나중에 상류 보안 수정이 나오면 tauri를 올리는 작업이 이 절차 때문에 늘어난다.
