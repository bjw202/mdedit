# SPEC-PREVIEW-022 구현 계획

결정이 바뀔 가능성이 큰 것부터 적었다. 이 계획은 안 X를 기준으로 한다. §D(열린 결정)를 먼저 보라.

## A. 사전 확인 사항 (plan 단계에서 읽은 사실)

- 기준: `main` `cdaadcf`, 브랜치 `WT-html-charset`. 이 SPEC의 `<base>`는 `$(git merge-base origin/main HEAD)`이며 plan 시점 값은 `cdaadcf`다.
- `src-tauri/src/lib.rs`는 `tauri::Builder`에 URI 스킴을 등록하지 않는다(`register_uri_scheme_protocol`·`register_asynchronous_uri_scheme_protocol` grep 결과 0건, 종료 코드 1). 사용 중인 플러그인 4개(opener, shell, dialog, single-instance)의 소스에도 스킴 등록이 없다(같은 grep, 종료 코드 1). 그래서 지금 asset 출처는 원격으로 분류된다(research.md §3).
- `src-tauri/Cargo.lock`: `tauri` 2.10.3, `source = "registry+https://github.com/rust-lang/crates.io-index"`.
- 레지스트리의 tauri 2.10.3 소스: 143개 파일(숨김 파일 `.cargo-ok`, `.cargo_vcs_info.json` 포함), 1.6 MB, `LICENSE_MIT`·`LICENSE_APACHE-2.0` 포함. CR(`\r`)이 든 텍스트 파일은 없다(`grep -rlI $'\r'` 출력 없음).
- 저장소 `.gitignore`가 vendor 경로를 빠뜨리지 않는다: 143개 경로를 `src-tauri/vendor/tauri/…`로 바꿔 `git check-ignore --no-index -v --stdin`에 넣으면 출력 없음, 종료 코드 1.
- `.gitattributes`: `* text=auto eol=lf`(#79의 LF 정책). 바이너리 확장자만 `binary`로 지정되어 있다.
- tauri `build.rs`는 빌드 때 `permissions/<plugin>/autogenerated/`에 문서를 쓴다(`tauri-2.10.3/build.rs:427-435`). 빌드 스크립트는 패키지 디렉터리에서 돌므로 vendor 사본 안에 쓴다.
- v0.20.0 릴리스(`50ad99e`)도 tauri 2.10.3을 쓴다(`git show 50ad99e:src-tauri/Cargo.lock`). SPEC-PREVIEW-020은 그 뒤에 병합되었으므로 v0.20.0의 Windows 기본 보기는 아직 선명 모드다. 원본 보기는 토글로 고른다.
- `release.yml`은 `v[0-9]+.[0-9]+.[0-9]+` 태그 push에서만 돌고 초안 릴리스만 만든다(게시는 사람이 한다). `-rc` 같은 프리릴리스 태그로는 돌지 않는다. 병합 전에 Windows 빌드를 만드는 CI 경로는 없다.
- `core:default`는 `core:app:default`를 통해 `allow-version`을 허용한다(`tauri-2.10.3/permissions/app/autogenerated/reference.md:7`). 부작용 없는 플러그인 명령 탐침(`plugin:app|version`)으로 쓴다.
- Rust 테스트는 CI에서 돌지 않는다. 명령: `~/.cargo/bin/cargo test --manifest-path src-tauri/Cargo.toml <filter>`.

## B. 접근 방식 (안 X)

1. **tauri 패치 방식 (가장 바뀔 수 있는 결정)**: 레지스트리의 `tauri-2.10.3/`을 `src-tauri/vendor/tauri/`에 숨김 파일까지 그대로 복사하고, `src-tauri/Cargo.toml`에 `[patch.crates-io] tauri = { path = "vendor/tauri" }`를 더한다. `Cargo.lock`의 `tauri` 항목은 `source` 줄이 사라진다. 다른 tauri 계열 크레이트(`tauri-build`, `tauri-macros`, `tauri-utils`, `tauri-runtime-wry`)는 그대로 레지스트리에서 받는다. X2를 고르는 경우는 §D-1을 보라. 그 경우 이 항목과 AC-001~004를 다시 쓴다.
2. **판정 규칙**: 새 파일 `src-tauri/vendor/tauri/src/protocol/asset/charset.rs`에 순수 함수 `html_content_type(mime: &str, full_body: Option<&[u8]>) -> String`을 둔다(표준 라이브러리만 사용). `asset.rs`에서 `mod charset;`로 쓴다.
3. **핸들러 수정 범위 (감사 D4 반영)**: `asset.rs` 100행(`resp = resp.header(CONTENT_TYPE, &mime_type);`)은 **그대로 둔다**. Range 분기(단일·다중 범위)와 HEAD 분기도 손대지 않는다. Range도 HEAD도 아닌 마지막 `else` 분기(227-241행, HEAD 분기는 223-226행) 안에서만, 본문 `buf`를 얻은 뒤 `resp.headers_mut()`로 `CONTENT_TYPE`을 `insert`(덧붙이기가 아니라 교체)한다. 값은 `html_content_type(&mime_type, Some(&buf))`다. `HeaderMap::insert`는 같은 이름의 기존 값을 바꾸므로 다른 헤더의 이름·값·순서가 구조적으로 그대로 남는다. 다중 범위 응답에 `Content-Type`이 두 번 실리는 지금의 동작(100행과 184-187행)도 손대지 않으므로 그대로다. 결과가 `mime_type`과 같으면(HTML이 아니거나 UTF-8이 아닌 경우) 교체하지 않는다. 그래서 그 응답들은 구성상 지금과 같은 코드 경로만 지난다. 이 수정은 기존 줄을 지우지 않는 순수 추가가 된다(AC-004).
4. **테스트 배치**: 앱 크레이트 통합 테스트 `src-tauri/tests/asset_charset.rs`가 `#[path = "../vendor/tauri/src/protocol/asset/charset.rs"] mod charset;`로 같은 파일을 불러 단위 표를 검증한다. tauri 크레이트의 개발 의존성 없이 앱의 `cargo test`로 돈다. 같은 파일에 상류 추적 가드(REQ-010)를 둔다: `Cargo.lock`을 읽어 `tauri`가 2.10.3이고 `source` 줄이 없음을 단언한다.
5. **fixture**: `src-tauri/tests/fixtures/charset/` 아래에 두고, 단위 테스트가 `include_bytes!`로 같은 파일을 읽는다(실기기 확인과 단위 표가 같은 바이트를 쓴다). 목록은 acceptance.md § Fixture.
6. **in-page 탐침 (감사 D6 반영)**: fixture HTML은 ASCII 스크립트로 `document.characterSet`과 `fetch(location.href)` 응답의 `content-type`을 화면에 쓴다. **판정 신호는 `document.characterSet`이다.** 문서 자체가 어떤 인코딩으로 해석됐는지를 직접 보여 준다. fetch는 문서 요청과 다른 별도 요청이므로 그 `content-type`은 보조 기록일 뿐이다. 원본 보기는 스크립트를 허용한다(선명 모드에서는 동작하지 않으며 그래도 된다).
7. **줄바꿈·바이트 보존 (감사 D5 반영)**: `.gitattributes`에 두 줄을 더한다. `src-tauri/vendor/** -text`는 Windows 체크아웃에서도 vendor 사본을 레지스트리와 바이트 단위로 같게 둔다. `src-tauri/tests/fixtures/charset/** binary`는 EUC-KR·UTF-16 fixture의 바이트 변환과 diff 깨짐을 막는다.

## C. 마일스톤 (순서)

- **M0 — 재현 (코드 변경 전, REQ-011)**
  - fixture를 먼저 만든다(M1의 일부를 당겨 온다. fixture와 `.gitattributes` 줄만 만들고 핸들러 코드는 바꾸지 않는다).
  - macOS: 기준 커밋(`<base>`)의 로컬 빌드에서 `utf8-no-meta.html`, `euckr-meta.html`을 원본 보기(토글)로 연다. 구현자가 직접 기록한다.
  - Windows: 사용자가 이미 설치된 v0.20.0 릴리스 빌드(tauri 2.10.3, 새 빌드 불필요)에서 같은 두 파일을 원본 보기로 연다. v0.20.0의 Windows 기본은 선명 모드이므로 토글로 원본 보기를 고른다. 사용자가 `probe` 출력과 화면을 알려 준다.
  - 기록: OS, 빌드(SHA 또는 버전), `characterSet`(판정), fetch `content-type`(보조), 한글 표시(깨짐/정상), 캡처 경로.
  - 멈춤 규칙(OS별):
    1. 어느 OS든 `content-type`에 이미 charset이 있으면 멈추고 다시 계획한다(차단 보고).
    2. 한 OS 이상(Windows 예상)에서 `utf8-no-meta.html`의 한글이 깨지면 진행한다. 깨지지 않은 OS는 그 사실과 `characterSet`만 기록한다.
    3. 두 OS 모두에서 깨지지 않으면 멈춘다(원인 가설이 틀림).
  - 기다리는 동안: Windows 기록이 아직 없어도 macOS에서 M1 RED(테스트만 작성)는 진행할 수 있다. 어느 OS에서든 재현이 기록되기 전에는 GREEN 커밋(M2)을 만들지 않는다. macOS가 재현되지 않고 Windows 기록도 없으면 M1에서 멈추고 차단 보고를 돌려준다.
- **M1 — RED**
  - `src-tauri/tests/asset_charset.rs`를 쓴다(단위 표 + 상류 추적 가드). `charset.rs`와 패치가 없으므로 컴파일 실패 또는 가드 실패를 확인하고 출력을 progress.md에 붙인다.
  - fixture 바이트 확인: 커밋 후 `xxd`로 EUC-KR·UTF-16 fixture가 바뀌지 않았는지 본다(research.md R-3).
- **M2 — GREEN** (M0 재현 기록이 하나 이상 있을 때만)
  - 복사(저장소 루트에서, `src-tauri/vendor/`가 없는 상태에서):
    ```bash
    mkdir -p src-tauri/vendor
    cp -R ~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.10.3 src-tauri/vendor/tauri
    ```

  - `[patch.crates-io]`, `charset.rs`, `asset.rs` 수정(§B-3).
  - `cargo build`, `cargo test --test asset_charset` 통과.
  - 첫 `cargo build` 뒤 `git status --short src-tauri/vendor`로 `build.rs`가 `permissions/*/autogenerated/` 파일을 바꿨는지 본다. 바뀌었으면 그 경로와 `git diff --stat`을 progress.md에 적는다. 바뀐 파일은 레지스트리 원본으로 되돌리지 않고 빌드 결과를 커밋한다. 그래야 다음 빌드에서 작업 트리가 깨끗하다. 그 경로는 AC-004에서 "예상된 재생성"으로 따로 센다.
  - `cargo fmt`·`cargo clippy`가 vendor 디렉터리를 건드리지 않는지 확인한다(research.md R-4).
- **M3 — 정적 게이트**: AC-002(호출 1곳), AC-003(가드), AC-004(상류 diff 허용 목록, `cargo build` 뒤 실행), AC-005(스킴 등록 0건), AC-006(변경 파일 이름 목록), AC-007(회귀 스위트).

- **M5 — 마무리**: `charset.rs`에 `@MX:NOTE`(판정 규칙과 사유), `asset.rs` 교체 줄에 `@MX:WARN`(상류 패치 지점, `@MX:REASON`: tauri 업그레이드 시 research.md §6 절차 필요). 주석 언어는 `code_comments: ko`. `[patch.crates-io]` 위에 한 줄 주석으로 research.md §6 위치를 적는다.
- **병합 뒤 — Windows 확인 (SPEC은 `implemented`)**: sync에서 SPEC은 `implemented`까지만 닫는다(SPEC-PREVIEW-020과 같은 방식). 다음 릴리스 태그가 만든 초안 릴리스의 Windows 설치 파일로 사용자가 AC-009·010·011을 확인하고 빌드 SHA를 기록한다. 모두 PASS이면 `completed`로 닫는 PR을 따로 올린다. 더 일찍 확인하는 방법(사용자가 고른다): (a) 사용자가 Windows에서 브랜치 HEAD를 `npm run tauri build`로 로컬 빌드, (b) 사용자가 승인한 정식 버전 태그로 초안 릴리스를 먼저 만든다(`-rc` 태그는 `release.yml`이 돌지 않는다). Windows 탐침에서 하나라도 ok이면: 진행을 멈추고, 초안 릴리스를 게시하지 않고, 패치를 되돌리거나 고치는 SPEC 개정을 연다(acceptance.md AC-011).

## D. 열린 결정 (run 시작 전 사용자 확인 필요)

1. 패치 전달 방식 — 계획은 안 X(tauri 소스 1.6 MB·143개 파일을 `src-tauri/vendor/tauri/`에 들여와 `path`로 패치)다. 사용자가 구현 승인 때 변형 X2(사용자 GitHub 포크를 `git`+`rev`로 패치, 릴리스 CI가 포크를 받을 수 있어야 함)를 고를 수 있다. 두 안은 보안 성질과 바뀌는 코드가 같고 요구사항(spec.md §2)도 같다. 그러나 **X2를 고르면 AC-001~004는 그대로 쓸 수 없다.** AC-001·002는 vendor 경로(`#[path]`, grep 대상)에 기대고, AC-003은 `Cargo.lock`의 `tauri`에 `source` 줄이 없음을 판정하는데 X2에서는 `source = "git+…"`가 있으며, AC-004는 vendor 디렉터리와 레지스트리를 diff한다. X2를 고르면 이 네 AC와 §B-1·§B-4·M2를 다시 계획하고 plan-audit 재감사를 받은 뒤 run에 들어간다.
2. 안 A(앱 `asset` 스킴 재등록)는 기각으로 확정한다. 근거는 research.md §3이며, 코디네이터 세션이 `tauri-2.10.3/src/webview/mod.rs:1698-1720`(앱이 등록한 스킴을 로컬로 판정)과 `:1769-1775`(로컬이면 `Origin::Local`)를 다시 읽어 확인했다. 최신 tauri 2.12.5에서도 같은 판정이 남아 있다(research.md §4). 사용자가 그래도 안 A를 원하면 이 SPEC을 다시 계획한다.
3. tauri 상류에 "asset 응답에 charset" 이슈·PR을 올릴지. 기본은 이 SPEC 밖이다. 상류가 고치면 research.md §6 절차로 패치를 걷어낸다.
4. Windows 확인 시점: 기본은 병합 뒤 다음 릴리스 빌드다. 더 일찍 하려면 사용자가 로컬 Windows 빌드나 정식 버전 태그(초안 릴리스)를 고른다(§C 병합 뒤 항목).

## E. 위험 관리 요약

- 보안: 안 X는 앱의 스킴 등록이 없다는 성질에 기대며, AC-005가 정적으로, AC-011이 실기기로 지킨다. 병합 전에는 macOS 탐침이, 게시 전에는 Windows 탐침이 막는다.
- 상류 어긋남: REQ-010 가드와 research.md §6 절차.
- 원인 가설: M0 OS별 멈춤 규칙.
- 패치가 조용히 빠짐: 로컬 가드(REQ-010)와 릴리스 빌드 실기기 확인(AC-009). CI 가드는 범위 밖이다(spec.md §6).
- 잔여 위험: 들여온 사본에 나중에 상류 보안 수정이 나오면 tauri를 올리는 작업이 이 절차 때문에 늘어난다. Windows 판정은 병합 뒤에야 나온다.

## F. 범위·규모 (안 X)

- 신규: `src-tauri/vendor/tauri/**`(기계적 복사, 숨김 파일 포함), `src-tauri/vendor/tauri/src/protocol/asset/charset.rs`, `src-tauri/tests/asset_charset.rs`, `src-tauri/tests/fixtures/charset/*`(acceptance.md § Fixture).
- 수정: `src-tauri/vendor/tauri/src/protocol/asset.rs`(else 분기의 교체 한 곳과 `mod charset;`), `src-tauri/Cargo.toml`(`[patch.crates-io]`), `src-tauri/Cargo.lock`, `.gitattributes`(두 줄). `build.rs`가 다시 쓴 `src-tauri/vendor/tauri/permissions/*/autogenerated/*`가 있으면 그것도 포함한다.
- 바꾸지 않음: `src/**`, `index.html`, `src-tauri/src/**`, `src-tauri/capabilities/**`, `src-tauri/tauri.conf.json`, `src-tauri/build.rs`.
- 새로 쓰는 코드 약 100~200줄(판정 함수, 핸들러 교체, 테스트). Tier M.
