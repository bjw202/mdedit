SPEC-PREVIEW-015 M1b — 다이어그램 수식 해석기(pele math + KaTeX) 보강 측정

생성: 2026-10-26T09:03:08.909Z · 브라우저: playwright 1.58.2 webkit 26.0 (headless, macOS) / playwright 1.58.2 chromium 145.0.7632.6 (headless, macOS) · 단위: vitest 2.1.9 jsdom 28.1.0 (node v24.12.0, setup src/test/setup.ts) · KaTeX 0.16.44 · pele 1.10.0 · 기계 확인 표는 checks.md의 "M1b" 절, 원본 수치는 evidence/m1b-*.json. M1 보고서로

판정(통과/보류)과 해석기 출력 방식·DOCX 처리 방식은 사용자 판정 대기입니다. 이 보고서는 근거만 제시합니다.

주요 결과

  1. F11 WebKit에서 KaTeX HTML 출력은 자리를 벗어나 그려진다. 레이아웃 상자(getBoundingClientRect)는 foreignObject 안에 있지만, 화면에 칠해지는 위치는 SVG 왼쪽 위 구석이다. 수식이 있는 화면과 수식을 지운 화면의 픽셀 차이 중 foreignObject 상자 안에 떨어진 비율이 webkit에서 html·mathml(KaTeX .katex 감쌈) 모두 0, mathml-bare(감쌈 제거) 1이다. chromium은 세 방식 모두 1이다. 원인 후보는 앱이 전역으로 싣는 katex.min.css의 .katex{position:relative} 등 위치 지정 규칙이다 — .katex를 position:static으로 덮으면 mathml은 제자리에 그려지고(탐색 실험), html 출력은 내부 .vlist 요소들도 상대 위치를 써서 그렇게 해도 고쳐지지 않았다(run-m1b-position.mjs, mathml+static · html+static · html).
  2. 같은 현상이 지금 mermaid에도 보인다. KaTeX CSS를 실은 페이지에서는 mermaid strict 출력의 수식도 webkit에서 왼쪽 위로 몰린다(img/m1b-18-math-label-mermaid-light.png). M1 비교 페이지는 KaTeX CSS를 싣지 않아 정상으로 보였다. 앱(WKWebView, KaTeX CSS 전역 로드)의 현재 표시는 MANUAL-3로 확인해야 한다 (추정 — 앱에서 미확인).
  3. KaTeX output:'mathml'에서 바깥 <span class="katex">를 뗀 방식(mathml-bare)은 미리보기(webkit·chromium, 라이트·다크), HTML 내보내기(KaTeX CSS·글꼴 없이), DOCX PNG(webkit·chromium) 세 경로 모두에서 제자리에 수식으로 그려졌다.
  4. 정화: 별도 인스턴스 DOMPurify(window)에 건 훅은 공유 sanitizeSvg 호출에서 한 번도 실행되지 않았고(0회), 공유 경로의 M1 픽스처 출력은 앞·중간·끝 세 번 모두 바이트 단위로 같았다. 반대로 새 인스턴스는 공유 href 훅을 물려받지 않으므로 다이어그램 경로에 다시 걸어야 한다(물려받지 않으면 data: href가 남음 — 측정).
  5. DOCX 캔버스는 오염되지 않는다. webkit 26·chromium 145에서 foreignObject가 든 SVG를 data URI → Image → canvas로 그린 뒤 toDataURL·toBlob·getImageData가 모두 성공했다. 다만 이미지 안에는 문서 CSS가 들어가지 않아 KaTeX html 출력은 위첨자·분수·근호가 깨진 글자로 나온다.
  6. CSP: pele 수식 렌더 시나리오(html·mathml·mathml-bare)는 위반 이벤트 0건이다. 모든 시나리오(수식을 그리지 않는 load-only 포함)에서 페이지 로드 때 콘솔 거부 1건이 있다 — Vite가 4KB 미만인 KaTeX_Size3-Regular.woff2를 data: URI로 CSS에 넣고, 앱 CSP에는 font-src가 없어 default-src(data: 없음)로 막힌다. 앱 프로덕션 빌드 CSS에도 같은 data:font/woff2가 들어 있음을 확인했다(기존 결함, pele와 무관). 위반 이벤트 5건은 mermaid 수식 렌더(webkit)에서만 나왔다.
  7. jsdom: DOM 측정 해석기는 크기 0을 받아 null을 돌려주고, pele는 $$…$$ 원문을 글자로 그린다. 텍스트 길이 추정 측정은 결정적이다. 단위 테스트에서는 실제 수식 크기를 확인할 수 없다.
