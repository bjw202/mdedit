# SPEC-AI-017 인수 기준

프롬프트 기준은 계획 단계 실측에 실제로 보낸 파일(`spike/captures/{table-column,diagram-node}.{system,user}.txt`)을 run 단계에서 `src-tauri/tests/fixtures/point-table-system.txt`·`point-table-user.txt`·`point-diagram-system.txt`·`point-diagram-user.txt` 로 **복사**한 것이다. 미리보기 쪽 테스트는 실제 `renderMarkdown` 출력과 실제 `renderDiagram` SVG 를 쓴다(손으로 만든 마크업 금지).

공통 예시 문서(이하 「예시 문서」, 줄 번호는 0부터):

````markdown
# 요금

| 요금제 | 월 요금 | 저장 공간 |
|---|---:|---|
| 무료 | 0원 | 5GB |
| 기본 | [9,900원](https://example.com/p) | 100GB |
| 프로 | 19,900원 | 1TB |

```mermaid
flowchart LR
  A[장바구니] --> B[주문서 작성]
  B --> C{결제}
  C -->|성공| D[주문 완료]
  C -->|실패| B
```

- 목록 안 표
  | a | b |
  |---|---|
  | 1 | 2 |
````

추가 다이어그램 샘플(이하 「S3 샘플」)은 `spike/sanitize-data-id.test.ts.txt` 의 `SAMPLES` 소스를 그대로 쓴다(flowchart·sequence·state·class·er·mindmap·pie·gantt).

## 자동 테스트 (vitest · cargo test)

### AC-AI17-001 — 보이는 조건 (REQ-AI17-001, 015)
- Given: 예시 문서, 판정 함수에 (사용자 토글, 정책 잠금 캐시, 보기 모드) 조합을 준다.
- Then: (켜짐, 잠금 없음, `split`) 에서만 가리키기가 활성이고, 토글 꺼짐·정책 잠금·`editor`·`preview` 보기에서는 비활성이다. 입력창이 열린 뒤 정책 잠금 캐시를 참으로 바꾸거나 사용자 토글을 끄고 보내면 요청이 만들어지지 않고 입력창이 닫힌다(보내기 시점 판정).

### AC-AI17-002 — 대상 판정 (REQ-AI17-004)
- Given: 예시 문서를 `renderMarkdown` + `renderDiagram` 으로 그린 DOM, 그리고 S3 샘플 SVG.
- Then: 머리 `월 요금` 칸 → 열(열 번호 2), `9,900원` 링크 글자 → 칸(행 2, 열 2), 노드 `C` 의 글자 요소 → 노드 `C`, 연결선·연결선 글자 → 대상 아님, 목록 안 표의 칸 → 대상 아님. S3 샘플: state 의 `root_start`·`root_end` → 대상 아님, `대기` → 대상(한글 ID 낱말 경계), pie·gantt → 대상 없음.

### AC-AI17-003 — 노드 마크업 계약 (REQ-AI17-004)
- Then: S3 샘플 중 flowchart·sequence·state·class·er·mindmap 의 `renderDiagram` SVG 에서 `g.pele-node[data-id]` 를 찾을 수 있고, 노드 안쪽 `text` 요소에서 `closest('g.pele-node')` 로 ID 를 되찾는다. sequence 는 같은 ID 의 노드가 2개다(pele 를 올려 이 계약이 깨지면 실패한다).

### AC-AI17-004 — 순번 블록 찾기 (REQ-AI17-005, 009)
- Then: 예시 문서에서 표 대상의 블록 텍스트는 표 다섯 줄(2~6줄) 그대로이고, `기본` 행 칸의 소스 줄은 5줄이다. 노드 대상의 요청 텍스트(`selection`)는 펜스 안 코드 다섯 줄(9~13줄), 카드 범위는 펜스 줄을 포함한 일곱 줄(8~14줄). 목록 안 표가 DOM 에서 두 번째 `table` 이어도 첫 번째 표의 순번 대응이 흔들리지 않는다.
- And: 표 **앞에** 여러 줄 인라인 `<svg>…</svg>`(5줄) 블록을 넣은 문서에서도 표·다이어그램의 블록 텍스트와 줄 범위가 에디터 문서 기준으로 맞다(`data-line` 어긋남에 영향받지 않음).
- And(파서 일치, 계획 감사 2차 재현 사례): (a) 펜스 줄이 `` ```mermaid `` 뒤에 공백이 붙은 다이어그램 2개가 있는 문서에서 두 번째 다이어그램 노드를 누르면 두 번째 펜스가 대상이다. (b) 표 모양 줄이 든 `$$ … $$` 수식 블록 뒤에 표가 있는 문서에서 그 표의 칸을 누르면 그 표가 대상이다(수식 블록이 표로 세어지지 않음).
- And(일치 확인): 소스 파싱 결과를 일부러 바꿔 다이어그램 수·`data-diagram` 내용·머리 칸 수 중 하나를 DOM 과 어긋나게 하면 결과가 「가리킬 수 없음」이고 요청이 만들어지지 않는다. 반대로 라벨에 `&amp;`·`&lt;`·`&copy` 가 든 정상 다이어그램(예: `A[R&amp;D] --> B[x &lt; y]`)은 일치 확인을 통과해 대상이 된다(비교는 `previewDiagramInput` 기준). 공용 파서 구성을 꺼낸 뒤에도 기존 `renderMarkdown` 테스트가 수정 없이 통과한다.

### AC-AI17-005 — 낡은 미리보기 (REQ-AI17-006)
- Given: 렌더 소스는 예시 문서.
- Then: 에디터 문서가 `기본` 행의 `100GB` 를 `200GB` 로 바꾼 것이면 ⌥+클릭 판정이 「낡음」이고 요청이 만들어지지 않는다. 표 밖(제목 줄)만 바꾼 문서는 낡음이 아니다. 입력창을 연 뒤(낡음 아님) 에디터에서 표 칸을 고치고 보내면 보내기 시점 판정이 「낡음」이고 요청이 만들어지지 않는다.
- And(강조 복원 판정, REQ-AI17-014): 카드를 만든 뒤 새 렌더 소스가 제목 줄만 바뀐 것이면 강조 복원 판정이 「복원」, 대상 표의 칸이 바뀐 것이면 「지움」이다.

### AC-AI17-006 — 대상 정보 문자열 (REQ-AI17-007)
- Then: 열 대상 = `대상: 열\n열 번호: 2 (왼쪽부터)\n열 머리: 월 요금`, 칸 대상(`9,900원`) = `대상: 칸\n행 번호: 2 (머리 행 다음부터)\n열 번호: 2 (왼쪽부터)\n열 머리: 월 요금\n칸 내용: [9,900원](https://example.com/p)`(소스 값), 노드 대상 = `대상: 노드\n노드 ID: C\n표시 글자: 결제`. 소스 행에 칸이 모자란 경우 마지막 줄은 `칸 내용: `(빈 값).

### AC-AI17-007 — 정리 (REQ-AI17-015)
- Then: 입력창이 열리고 가리키기 카드·미리보기 강조가 있는 상태에서 `runAiArtifactCleanup()` 을 부르면(사용자 토글 끄기·파일 전환의 공용 정리) 입력창이 닫히고, 가리키기 카드가 레지스트리에서 사라지고, 강조 클래스가 남은 요소가 없다.

### AC-AI17-008 — 입력창과 길이 (REQ-AI17-008, 009)
- Then: 대상 요약이 `열: 월 요금` / `칸: 2행 · 월 요금` / `노드: 결제 (C)`. Enter 로 보내고, Shift+Enter 는 줄바꿈, Esc 는 닫힘. `isComposing` 이 참이거나 `keyCode` 가 229 인 Enter 는 보내지 않는다. 공백뿐인 지시는 보낼 수 없다.
- And: 12,001자 표는 길이 안내 + 보내기 비활성, 12,000자 표는 보낼 수 있고 카드가 「아래에 삽입」 전용, 6,000자 표는 「바꾸기」·「아래에 삽입」 둘 다(SPEC-AI-013 안전선 별도).

### AC-AI17-009 — 요청 인자 (REQ-AI17-009)
- Then: 열 대상에 `연 요금으로, ×10` 을 보내면 `ai_request` 인자가 `feature: 'inline-edit'`, `presetKind: 'point-table'`, `selection` = 표 다섯 줄, `customInstruction: '연 요금으로, ×10'`, `pointer` = AC-006 의 열 문자열이고 `contextBefore`·`contextAfter` 가 없다. 노드 대상은 `presetKind: 'point-diagram'`, `selection` = 펜스 안 코드.

### AC-AI17-010 — 백엔드 조립 (REQ-AI17-010)
- Then: `point-table`(지시 `연 요금으로, ×10`, 대상 정보·블록 = S5 값)의 조립 결과가 `point-table-system.txt`·`point-table-user.txt` 와 바이트까지 같고, `point-diagram`(지시 `결제 앞에 캐시 노드 추가`)도 `point-diagram-*.txt` 와 같다. 추가 지시 `X` 를 주면 시스템 끝에 `\n\n추가 지시(재요청): X`, 사용자 재확인 블록의 `지시:` 줄 다음에 `\n추가 지시(재요청): X` 가 붙는다. 블록에 `mdedit_pointer` 가 들어 있으면 두 태그 이름에 같은 접미사가 붙는다. `pointer` 가 없거나 공백뿐이면 오류다. `allows_web()` 이 거짓이다.

### AC-AI17-011 — 검증과 재요청 (REQ-AI17-011)
- Given: 가리키기 카드 컨트롤러에 차례로 결과를 넣는다.
- Then:
  - 표: 유효한 다른 표 → 검토 단계. 표 뒤에 설명 문단이 붙은 출력 → 실패. 열 수가 다른 행이 있는 표 → 실패. 원본과 줄 끝 공백만 다른 표 → 실패(원본과 같음)이고 추가 지시는 `이전 결과가 원본과 같았다. 지시한 변경을 반영하라.`.
  - 다이어그램: 펜스로 감싼 유효하고 다른 코드 → 검토 단계(펜스 벗김). 펜스로 감싼 원본 코드 → 실패(원본과 같음). 문법 오류 코드 → 실패(오류 문구 동봉).
  - 첫 실패는 자동 재요청 1회(`exempt`, ↻ 횟수 불변), 같은 묶음의 두 번째 실패 → 오류 카드(「다시 시도」·「닫기」, 적용 버튼 없음). 「목록으로 정리」 폴백이 나타나지 않는다.
  - 오류 카드 「다시 시도」 또는 검토 카드 ↻ 로 시작한 새 묶음에서는 검증이 다시 일어나고 자동 재요청 1회를 다시 쓸 수 있다.
  - 기존 `table`·`diagram` 프리셋 카드의 검증 테스트는 수정 없이 통과한다.

### AC-AI17-012 — 결과 표시와 적용 (REQ-AI17-012, 013)
- Then: 검토 단계 카드에 결과 텍스트와 렌더된 모습(표: 미리보기 렌더러 출력의 `table`, 다이어그램: 미니 SVG)이 있다. 결과 표에 `![로고](https://example.com/a.png)` 와 `[링크](https://example.com)` 가 있으면 카드 안 표에는 `img` 요소와 `a` 요소가 하나도 없고 각각 `로고`·`링크` 글자만 있다(D17). 변환은 비활성 문서에서 하며, 테스트는 변환 함수가 `img` 를 활성 문서에 붙이지 않음을 확인한다. 버튼은 「바꾸기」(강조)·「아래에 삽입」. 2,001자 이상 블록 + 완결 `unknown` 이면 「바꾸기」가 사라지고 기존 안내 문구가 뜬다(SPEC-AI-013 그대로). 「바꾸기」 적용 후 문서는 블록 범위만 결과로 바뀌고(다이어그램은 `` ```mermaid `` 펜스 포함) 되돌리기 한 번으로 원래 문서와 같아진다. 적용 직전 블록 안 칸 하나를 고친 문서에서는 적용되지 않고 stale 카드(「원문이 바뀌어 적용할 수 없어요」)가 되며 문서는 그대로다. 「취소」 뒤 문서는 그대로다.

### AC-AI17-013 — 다른 기능 불변 (REQ-AI17-016)
- Then: 기존 프롬프트 조립 테스트(SPEC-AI-012·016 의 바이트 비교 포함)가 수정 없이 통과한다. 가리키기 요청의 claude 인자는 `--tools` 다음이 빈 문자열이고 `--allowedTools` 가 없으며, codex 인자에 `features.apps=false`·`features.shell_tool=false`·`features.view_image=false`·`web_search=disabled` 가 있다.

## 실제 브라우저 (Playwright webkit, `e2e/preview-pointing.spec.ts`)

### AC-AI17-014 — 포인터 순서와 정리 (REQ-AI17-001, 002, 003, 013, 014, 015)
- Given: 예시 문서, AI 켜짐, 분할 보기, `e2e/fixtures/tauri-v2-ai-mock.ts`.
- Then:
  1. 수정키(macOS ⌥) 없이 표 칸 클릭 → 입력창 없음. 칸 글자 드래그 → 텍스트가 선택되고 입력창 없음.
  2. ⌥ 누른 채 머리 `월 요금` 위로 이동 → 그 `th` 에만 강조. ⌥ 떼면 사라짐.
  3. ⌥+클릭 링크 칸(`9,900원`) → 입력창이 뜨고 브라우저 열기 호출(`open_url_in_browser`)이 **없다**. ⌥ 없이 같은 링크 클릭 → 열기 호출이 있다(기존 동작).
  4. 다이어그램 노드 `C` 의 글자 위 ⌥+클릭 → 입력창 요약 `노드: 결제 (C)`(M1 첫 확인 항목).
  5. 입력창에 지시를 넣고 Enter → `__AI_MOCK__.requests` 에 AC-009 인자의 요청 1건, 에디터에 카드가 뜨고, 미리보기의 대상이 강조된 채 남는다. 에디터에서 제목 줄을 고쳐 미리보기가 다시 그려져도 강조가 남는다. 대상 표의 칸을 고쳐 다시 그려지면 강조가 사라진다. 새로 가리켜 카드를 띄운 뒤 「취소」 → 강조가 사라진다.
  6. 보기 모드 `preview` 로 바꾼 뒤 ⌥+클릭 → 입력창 없음.
  7. 검토 카드와 강조가 있는 상태에서 설정의 AI 토글을 끄면 카드·강조가 사라진다(입력창이 열린 상태의 정리는 AC-007 vitest). 다시 켠 뒤 검토 카드가 떠 있는 동안 에디터에서 대상 표의 칸 하나를 고친 뒤 「바꾸기」 → stale 안내가 뜨고 문서의 그 표는 고친 상태 그대로다.
  8. 스크롤 동기: 예시 문서를 길게 늘린 뒤 에디터를 다이어그램 펜스 줄까지 스크롤하면 미리보기의 다이어그램이 보이는 영역에 들어온다(회귀 없음).

### AC-AI17-015 — macOS 실기기 전체 흐름 (REQ-AI17-001~015)

### AC-AI17-016 — Windows 실기기 (REQ-AI17-001, A3)
- Windows 에서 Alt+클릭과 Ctrl+클릭 각각으로 입력창이 뜨고, Alt 를 뗀 뒤 창 메뉴가 포커스를 가져가지 않는지 확인한다(Ctrl+클릭은 창 메뉴 문제가 없는 대안). macOS 에서는 ⌥+클릭만 입력창을 띄우고 Ctrl+클릭(컨텍스트 메뉴)은 띄우지 않는지 함께 확인한다. 기기가 없으면 미확인으로 남기고 sync 보고에 적는다.
