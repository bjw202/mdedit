## Summary

미리보기에서 **표의 열 머리·칸**이나 **다이어그램 노드**를 **⌥(Alt)+클릭**하면 작은 입력창이 뜬다. 지시(예: "연 요금으로, ×10", "결제 앞에 캐시 노드 추가")를 적으면, AI가 그 **블록 전체의 새 소스**를 돌려주고, 에디터의 기존 제안 카드가 **렌더된 모습**으로 결과를 보여 준다. 사용자는 미리보기(바뀌기 전, 대상 강조)와 카드(바뀐 뒤)를 나란히 보고 「바꾸기」로 확정한다(되돌리기 한 번).

에디터만 가진 강점: 마크다운 텍스트로는 **표의 열을 선택할 수 없고**, 다이어그램 소스는 ID·화살표가 섞여 있어 **노드를 고르기 어렵다**. 미리보기의 화면 위치와 소스 위치를 둘 다 아는 것은 에디터뿐이다.

## 사용자 확정 사항 (2026-11-13, 재검토 금지)

- U1. 범위는 **표와 다이어그램만**. 일반 문단은 제외(텍스트 선택 + 직접 입력보다 나은 점이 없다).
- U2. 가치: (1) 표의 열은 마크다운 텍스트로 선택할 수 없다 — 열 머리를 눌러 열을 지정한다. 넓은 표의 칸도 같다. (2) 다이어그램 소스는 ID·화살표가 섞여 있다 — 노드를 누르면 ID가 정해진다. (3) 확정 전에 렌더된 결과를 본다(다이어그램은 소스 차이만으로 판단하기 어렵다).
- U3. AI 기능은 에디터만 가진 강점에 기대야 한다. 지식 그래프·폴더 전체 기능은 하지 않는다.
- U4. 이 기능은 도구 없이 동작한다(텍스트만). 진행 순서: plan → 사용자 승인 → run → sync.

줄 사이는 `\n` 하나, 끝 줄바꿈 없음. `{c}` = 왼쪽부터 1로 시작하는 열 번호, `{r}` = 머리 행 다음부터 1로 시작하는 행 번호. `{머리}`·`{칸}` 은 소스 값을 앞뒤 공백 제거한 것, `{글자}` 는 렌더된 노드 글자(`textContent`)에서 연속 공백을 한 칸으로 줄이고 앞뒤 공백을 뺀 것(D14).

| 대상 | 문자열 |
|------|--------|
| 열 | `대상: 열\n열 번호: {c} (왼쪽부터)\n열 머리: {머리}` |
| 칸 | `대상: 칸\n행 번호: {r} (머리 행 다음부터)\n열 번호: {c} (왼쪽부터)\n열 머리: {머리}\n칸 내용: {칸}` |
| 노드 | `대상: 노드\n노드 ID: {data-id}\n표시 글자: {글자}` |

예: S5 의 열 대상은 `대상: 열\n열 번호: 2 (왼쪽부터)\n열 머리: 월 요금`, 노드 대상은 `대상: 노드\n노드 ID: C\n표시 글자: 결제`.

## Background — 현재 동작 (origin/main 1f3d4a5 기준)

- 미리보기: `usePreview.ts` 가 300ms 지연 뒤 `renderMarkdown` 으로 HTML 을 만들고, `MarkdownPreview.tsx` → `PreviewRenderer.tsx` 가 `dangerouslySetInnerHTML` 로 넣은 뒤 `.mermaid-container` 마다 `renderDiagram` 을 동기로 호출한다. 클릭 처리는 http(s) 링크를 시스템 브라우저로 여는 것뿐이다.
- 스크롤 동기: `useScrollSync.ts` 가 미리보기의 `[data-line]` 요소를 모아 줄 번호로 맞춘다(이 SPEC 은 바꾸지 않는다).
- AI 제안 카드: `ai-suggestion-card.ts` `startSuggestionCard(args, range, originalText)` 가 카드를 띄우고, `onComplete` 가 `presetKind` 로 표(`handleTableComplete`)·다이어그램(`handleDiagramComplete`, 목록 폴백 포함) 검증을 가른다. 두 검증 횟수(`tableAttempts`·`diagramAttempts`)는 카드 수명 동안 줄지 않는다. 적용은 `applySuggestion`(원문 재검증 + 단일 트랜잭션), 다이어그램은 `ensureMermaidFence` 로 펜스를 씌운다. 원본과 같은 결과는 `empty` 단계("이미 자연스러워서 바꿀 곳이 없어요")가 된다. 오류 카드 버튼은 「다시 시도」·「닫기」다. 길이 판정은 `ai-length-guard.ts` `evaluateSelectionGuard`(6,000자 초과 변환 계열은 「아래에 삽입」 전용, 12,000자 초과는 거부).
- 백엔드: `prompt.rs` `AiFeature::resolve` 가 `presetKind` 를 해석하고, 인라인 계열은 `build_inline_prompt_ex` 로 조립한다. `AiFeature::allows_web()` 은 리서치만 참이다. claude 는 항상 `--tools ""`(리서치 제외), codex 는 모든 요청에 도구 잠금 4쌍.
- AI 켜기: `aiPolicy.ts` `effectiveAiEnabled = !정책잠금 && 사용자토글`(정책 잠금은 캐시 값). 사용자 토글 끄기·파일 전환 시 `aiOffEffects.ts` `runAiArtifactCleanup` 이 카드 등을 정리한다.
- 보기 모드: `uiStore.ts` `ViewMode = 'split' | 'editor' | 'preview'`.

## Requirements (EARS)

### 모듈 1 — 진입과 대상

- **REQ-AI17-001** (State-driven) AI 가 실제로 켜져 있고(`effectiveAiEnabled`) 보기 모드가 `split` 이며 마크다운 미리보기가 보이는 동안, 미리보기는 대상(REQ-AI17-004)에 대한 ⌥(Alt)+클릭을 받아 입력창을 띄워야 한다. 이 조건은 ⌥+클릭 순간과 보내기 순간에 각각 판정하고, 보내기 순간에 거짓이면 요청을 만들지 않고 입력창을 닫아야 한다. 조건이 아닐 때 ⌥+클릭은 지금과 같이 동작해야 한다(입력창·강조 없음).
- **REQ-AI17-002** (Ubiquitous) ⌥ 없는 클릭, 드래그 텍스트 선택·복사, 링크 클릭(시스템 브라우저로 열기), 스크롤 동기는 이 기능이 있어도 지금과 같아야 한다. 대상 위의 ⌥+클릭은 기본 동작과 링크 열기를 막고 입력창만 띄운다.
- **REQ-AI17-003** (State-driven) ⌥ 를 누르고 있고 포인터가 대상 위에 있는 동안, 그 대상(노드는 같은 ID 의 모든 노드 그림, D16)에만 강조가 있어야 한다. ⌥ 를 떼거나 포인터가 대상을 벗어나면 강조가 사라져야 한다.
- **REQ-AI17-004** (Ubiquitous) 대상은 다음 셋뿐이다: 최상위 표의 `th`(열), 최상위 표의 `td`(칸), 최상위 mermaid 블록 SVG 의 `g.pele-node[data-id]` 중 그 ID 가 블록 소스에 낱말로(D4 경계 규칙) 나타나는 노드. 목록·인용 안의 표·다이어그램, 묶음·연결선, 노드가 없는 다이어그램, 소스에 없는 가상 노드는 대상이 아니다.

### 모듈 2 — 소스 대응

- **REQ-AI17-005** (Ubiquitous) 미리보기는 마지막 렌더에 쓴 소스를 HTML 과 함께 보관해야 하고, 클릭한 대상의 블록을 D11 의 순번 방식(미리보기와 같은 파서 구성)으로 찾아 블록 줄 범위·블록 텍스트·(표) 행 위치를 정해야 한다. D11 일치 확인이 하나라도 어긋나면 `이 블록은 가리킬 수 없어요` 를 보이고 요청을 만들지 않아야 한다.
- **REQ-AI17-006** (Event-driven) ⌥+클릭 순간과 보내기 순간 각각, 미리보기는 D11 낡음 판정을 해야 하고, 낡음이면 `미리보기를 갱신하는 중이에요. 잠시 뒤 다시 눌러 주세요` 를 보여 주고 요청을 만들지 않아야 한다.
- **REQ-AI17-007** (Event-driven) 블록이 확인되면, 미리보기는 「대상 정보 형식」 그대로 대상 정보를 만들어야 한다(열 머리·칸 내용은 소스에서, 노드 글자는 렌더된 노드에서, D14).
- **REQ-AI17-008** (State-driven) `selection` 길이(D10)가 12,000자를 넘는 동안 입력창은 길이 안내를 보이고 보내기를 막아야 하고, 6,000자 초과 12,000자 이하인 동안 보낸 요청의 카드는 「아래에 삽입」 전용이어야 한다.

### 모듈 3 — 입력과 요청

- **REQ-AI17-009** (Event-driven) 입력창이 열리면 대상 요약 한 줄(`열: {머리}` / `칸: {r}행 · {머리}` / `노드: {글자} ({ID})`)과 지시 입력칸을 보여야 한다. Enter(조합 중이 아닐 때, D15)로 보내고 Shift+Enter 로 줄을 바꾸며 Esc·바깥 클릭으로 닫혀야 하고, 공백뿐인 지시는 보낼 수 없다. 보내면 `feature` `inline-edit`, `presetKind` `point-table`/`point-diagram`, `selection` = 블록(표 줄 전체 / 펜스 안 코드), `customInstruction` = 지시, 새 인자 `pointer` = 대상 정보로 요청하고, 앞뒤 문맥은 보내지 않으며, 카드를 블록 범위(표 줄 전체 / 펜스 줄 포함 블록 전체, 보내기 순간의 에디터 문서 기준)에 띄워야 한다.
- **REQ-AI17-010** (Event-driven) `presetKind` 가 `point-table`/`point-diagram` 인 요청을 받으면, 백엔드는 그 요청을 「정본 문구」의 조립 규칙으로 조립해야 하고, 같은 입력이면 결과가 검증 기준 파일과 바이트까지 같아야 한다. `pointer` 가 없거나 공백뿐이면 오류를 돌려줘야 한다. 이 기능의 웹 허용은 거짓이다.

### 모듈 4 — 결과

- **REQ-AI17-011** (Event-driven) 가리키기 결과가 도착하면, 카드는 D8 (a)·(b) 로 검증해야 하고, 같은 요청 묶음(D8 (c))에서 첫 실패면 실패 이유(표 구조 오류 문구 / 다이어그램 오류 문구 / 원본과 같음이면 `이전 결과가 원본과 같았다. 지시한 변경을 반영하라.`)를 추가 지시로 붙여 자동으로 한 번 다시 요청하고(↻ 횟수에 세지 않음), 두 번째 실패면 실패 이유를 담은 오류 카드(「다시 시도」·「닫기」)로 끝내야 한다. 다이어그램 목록 폴백은 나타나지 않아야 하고, 기존 표·다이어그램 프리셋의 검증 동작은 바뀌지 않아야 한다.
- **REQ-AI17-012** (State-driven) 검증을 통과한 결과를 보여 주는 동안, 카드는 결과 텍스트와 함께 렌더된 모습(다이어그램: 기존 미니 렌더, 표: 미리보기 렌더러로 그린 뒤 이미지·링크를 글자로 바꾼 표, D17)을 보여 줘야 하고, 적용 버튼은 「바꾸기」(기본)와 「아래에 삽입」이며 SPEC-AI-013 안전선과 REQ-AI17-008 의 삽입 전용 판정을 따라야 한다.
- **REQ-AI17-013** (Event-driven) 「바꾸기」를 누르면 블록 범위 전체를 결과로 단일 트랜잭션에 바꿔야 하고(다이어그램은 `` ```mermaid `` 펜스로 감쌈), 되돌리기 한 번으로 원래 소스가 돌아와야 한다. 적용 직전 범위의 텍스트가 카드 원문과 다르면 적용하지 않고 stale 카드로 바꿔야 한다(D12). 취소·닫기는 소스를 바꾸지 않아야 한다.
- **REQ-AI17-014** (State-driven) 가리키기 카드가 열려 있는 동안, 미리보기의 대상은 강조되어 있어야 한다. 미리보기가 다시 그려지면, 같은 순번 블록의 텍스트가 카드를 만들 때와 같을 때만 다시 강조하고 다르면 강조를 지운다. 카드가 닫히면 강조가 사라져야 한다.

### 모듈 5 — 수명과 회귀

- **REQ-AI17-015** (Event-driven) 사용자가 AI 를 끄거나 파일이 바뀌면(`runAiArtifactCleanup`), 입력창·강조·가리키기 카드가 모두 닫혀야 한다. 정책 잠금은 반응형 상태가 아니므로 REQ-AI17-001 의 ⌥+클릭·보내기 시점 판정으로 막는다.
- **REQ-AI17-016** (Ubiquitous) 다른 모든 AI 기능의 시스템·사용자 프롬프트와 claude·codex 인자는 바이트까지 그대로여야 한다. 가리키기 요청의 claude 인자는 `--tools ""` 를, codex 인자는 도구 잠금 4쌍과 `web_search=disabled` 를 가져야 한다.

## Exclusions (What NOT to Build)

### Out of Scope — 이 SPEC에서 하지 않는 것

- 일반 문단·목록·코드 블록·수식 가리키기(U1).
- 행 단위 대상, 여러 칸·여러 노드 동시 선택, 묶음·연결선·연결선 글자 대상(D4).
- 미리보기 키보드 탐색·키보드 진입(D3).
- 미리보기 안에 "바뀔 모습"을 덮어 그리기(D5 — 카드가 보여 준다).
- 미리보기 전용 보기에서 자동으로 분할 보기로 바꾸기(D2).
- 목록·인용 안의 표·다이어그램(D4), 12,000자 넘는 블록(D10).
- 카드 범위를 문서 편집에 따라 옮기는 추적, 블록 안 편집의 즉시 침범 표시(D12 — 모든 AI 카드에 걸친 변경).
- 미리보기 `data-line` 정확도 개선(인라인 `<svg>` 줄 어긋남)과 다이어그램 컨테이너 `data-line`(D11 — 순번 방식이라 필요 없음). 미리보기 렌더 출력 자체는 바꾸지 않는다.
- 다이어그램 종류 바꾸기 감지·차단(검증은 문법만 본다), 결과의 칸 단위 차이 강조.
- 웹·셸 등 도구 사용(U4).
