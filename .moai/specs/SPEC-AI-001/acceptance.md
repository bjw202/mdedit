# Acceptance Criteria — SPEC-AI-001 (AI 기능 MVP M0+M1)

검증 방식:
- **Rust 순수 함수 유닛**: stream 파싱·stderr 분류·스폰 인자 조립·경로/정책 판정(`#[cfg(test)] mod tests`).
- **vitest + testing-library / 가짜 view**: 설정 모달·온보딩·프리셋 메뉴·길이 가드·mermaid 검증·제안 카드 적용·고스트 확정(`insertTable.test.ts` 가짜 view 스텁 선례).
- **Playwright(webkit)**: 렌더/상호작용 위주. **Tauri IPC는 Playwright에서 실행되지 않으므로** 실제 CLI 스폰·스트리밍은 Rust 유닛 + 수동 검증에 의존한다.
- **수동 실측(Windows 우선)**: 단축키 Ctrl 매핑, 저사양/백신 스폰 지연.

## 모듈 1 — AI 기반 인프라

### AC-AI-001: 스트리밍 릴레이 (REQ-AI-004, 007)

- **Given** claude가 설치·로그인된 상태에서 AI 요청이 시작될 때
- **When** CLI가 stdout으로 `text_delta` 라인을 순차 출력하면
- **Then** 각 델타가 `ai://chunk`로 릴레이되어 카드/고스트에 타이핑되듯 점진 표시되고, 완료 시 `ai://done`이 emit되며, 스트리밍 내내 취소 수단(Esc/버튼)이 노출된다.

### AC-AI-002: 격리 스폰 + Rust 프롬프트 조립 (REQ-AI-002, 003)

- **Given** AI 요청이 발생할 때
- **When** claude 어댑터가 프로세스를 스폰하면
- **Then** cwd는 앱 전용 빈 스크래치 디렉토리이고 `--setting-sources ""` + env `MAX_THINKING_TOKENS=0`이 적용되며, 프롬프트(기능 템플릿 + 컨텍스트 상한 절단)는 Rust에서 조립되고 프론트는 기능 종류 + 텍스트 조각만 전달한다.
- **And** 스크래치 디렉토리 생성이 실패(권한·디스크)하면 문서를 건드리지 않고 오류 카드로 처리한다.

### AC-AI-003: 동시 1개 + 요청 연타 (REQ-AI-005, 006, 008, 009) [edge]

- **Given** 진행 중(in-flight) AI 요청이 하나 있고, 별도로 검토 대기 중인 제안 카드가 하나 있을 때
- **When** 사용자가 새 AI 요청을 연타로 시작하면
- **Then** in-flight 요청만 취소(프로세스 kill)되고 취소된 쪽에 "새 요청으로 취소되었어요" 표시가 남으며, 검토 대기 카드는 유지되고, 동시에 2개 이상의 CLI 프로세스가 in-flight 상태가 되지 않는다.

### AC-AI-021: AiProvider trait 라우팅 + claude 단독 등록 (REQ-AI-001)

- **Given** 앱이 초기화되어 AI 프로바이더 레지스트리가 구성된 상태에서
- **When** 레지스트리에 등록된 어댑터를 열거하고 AI 요청을 발생시키면
- **Then** claude 어댑터가 정확히 1개만 등록되어 있고(codex 등 다른 어댑터 미등록), 모든 AI 요청이 `AiProvider` trait 인터페이스(id/detect/spawn/capabilities)를 경유해 라우팅된다(프론트가 CLI를 직접 호출하지 않는다).
- **And** trait 계약은 M4 codex 추가 시 어댑터 등록만으로 확장 가능한 형태를 유지한다(계약 형태 자체는 Design Notes 기준).

## 모듈 2 — 감지·설정·온보딩·정책

### AC-AI-004: 로그인 선제 감지 (REQ-AI-012, 015)

- **Given** claude가 설치되었으나 로그인되지 않은 상태일 때
- **When** 앱이 AI 감지를 실행하면
- **Then** 로그인 미완료가 실제 AI 호출 전에 판정되고, ✨ 진입점은 숨겨지지 않고 "연결 필요" 상태로 표시되며, 클릭 시 앱 내 연결 안내 모달이 열린다(첫 클릭이 실패 카드가 되지 않는다).

### AC-AI-005: 설정 모달 + 고지 배너 (REQ-AI-011, 013)

- **Given** Header에 설정(톱니) 버튼이 렌더된 상태에서
- **When** 사용자가 톱니 버튼을 클릭하면
- **Then** 설정 모달 다이얼로그가 열리고 첫 섹션이 AI 설정이다.
- **And** claude가 설치·로그인으로 최초 활성화될 때 "선택 텍스트와 문서 일부가 처리를 위해 전송됩니다" 데이터 전송 고지 배너가 1회 표시된다.

### AC-AI-006: 연결 온보딩 위저드 (REQ-AI-014, 018) [edge]

- **Given** claude 미설치 사용자가 온보딩에 진입할 때
- **When** 위저드가 표시되면
- **Then** OS 감지(Windows 우선) → 설치 명령 복사 버튼 → 터미널 안내 → 로그인 안내 → [다시 확인] 자동 재감지 단계가 앱 내에서 완결되고, "터미널에서 claude를 실행하세요" 식으로 사용자를 앱 밖에 방치하는 문구가 없다.

### AC-AI-007: 조직 정책 kill-switch (REQ-AI-017) [edge]

- **Given** 환경변수 `MDEDIT_AI_DISABLED=1` 또는 설정 디렉토리 정책 파일이 존재하는 상태로 앱이 시작될 때
- **When** 설정 모달의 AI 섹션을 열면
- **Then** 모든 AI 기능(✨·고스트·요청)이 강제 비활성화되고 설정 토글이 잠금 표시된다.

### AC-AI-022: 고급 모델 지속 토글 → sonnet (REQ-AI-016)

- **Given** 설정 모달 AI 섹션의 "고급 모델 사용" 토글이 **켜진** 상태에서
- **When** 사용자가 임의의 AI 요청(다듬기·이어쓰기 등)을 발생시키면
- **Then** 해당 요청이 sonnet 모델로 스폰된다.
- **When** 토글이 **꺼진** 상태에서 동일 요청을 발생시키면
- **Then** 요청이 기본 haiku 모델로 스폰된다.
- **And** 이 지속 설정은 REQ-AI-025의 "↻ 3회 소진 시 1회성 sonnet 폴백"(AC-AI-011)과 독립적이다 — 토글은 이후 모든 요청에 지속 적용되고, 폴백은 단발성이다.

## 모듈 3 — 인라인 편집 UX

### AC-AI-008: ✨ 진입 + 프리셋 메뉴 (REQ-AI-019, 020)

- **Given** 에디터에 텍스트를 선택한 상태에서
- **When** 사용자가 선택하면
- **Then** 선택 끝에 ✨ 버튼이 뜨고 우클릭 메뉴에도 "✨ AI로 편집"이 노출되며, ✨를 열면 프리셋 5종(다듬기 / 개요로 정리 / 표로 만들기 / 다이어그램으로 / 짧게 줄이기) + "직접 입력..."이 표시된다.
- **And** "직접 입력..." 선택 시 한 줄 입력창으로 전환되고 Esc 또는 ← 버튼으로 프리셋 메뉴에 복귀한다.

### AC-AI-009: 제안 카드 적용 + 단일 트랜잭션 (REQ-AI-021, 022)

- **Given** 어색한 문단을 선택해 "다듬기"를 요청하고 응답이 완료된 상태에서
- **When** 제안 카드가 표시되고 사용자가 [✓ 바꾸기]를 클릭하면
- **Then** 원문이 제안으로 교체되고 카드가 사라지며, Undo(Mod+Z) 한 번에 원문이 복원된다(단일 트랜잭션).
- **And** 카드에는 즉석 방향 지시 입력칸과 [↻ 다시]·[✕ 취소]가 있고, 변환 계열은 [⤵ 아래에 삽입]이 함께 제공된다.

### AC-AI-010: 다이어그램 검증 + 폴백 (REQ-AI-023, 024) [edge]

- **Given** 절차 문단을 선택해 "다이어그램으로"를 요청할 때
- **When** 응답 mermaid 코드가 로컬 파서(`securityLevel:'strict'`) 검증을 통과하면
- **Then** 카드에 코드블록 + 미니 렌더 미리보기가 표시되고 [✓ 아래에 삽입]으로 원문 유지 + 코드블록 삽입된다.
- **And** 검증이 실패하면 오류 메시지를 동봉해 1회 자동 재요청하고, 재실패 시 "목록으로 정리해드릴까요?" 대체 산출물을 제안한다.

### AC-AI-011: ↻ 3회 소진 → sonnet 폴백 (REQ-AI-025) [edge]

- **Given** 제안 카드에서 방향 없는 ↻ 재요청을 연속 3회 수행한 상태에서
- **When** 3회가 소진되면
- **Then** 방향 지시 입력 안내와 함께 "[⚡ 고급 모델로 다시 시도]" 인라인 제안이 표시되고, 클릭 시 설정 진입 없이 1회성 sonnet 재요청이 발생한다.

### AC-AI-012: 선택 길이 가드 (REQ-AI-026, 027) [edge]

- **Given** 에디터에서 텍스트를 선택할 때
- **When** 선택이 2,000자를 초과하면
- **Then** 편집(교체) 프리셋이 비활성화되고 "문단 단위로 나눠 선택해주세요" 안내가 표시된다(침묵 처리 없음).
- **And** 짧게 줄이기·개요로 정리·표로 만들기는 4,000자까지 허용하되 결과는 "아래에 삽입"만 가능하고, 선택 텍스트를 절단한 결과로 선택 전체를 교체하지 않는다.

## 모듈 4 — 섹션 채우기 (고스트)

### AC-AI-013: 힌트(토큰 0) → 고스트 스트리밍 (REQ-AI-028, 029)

- **Given** 커서가 빈 헤딩 바로 아래(또는 문서 끝)에 있을 때
- **When** 커서가 3초 이상 멈추면
- **Then** AI 요청·토큰 소모 없이 로컬 판정만으로 "이 섹션 채우기"(빈 섹션) 또는 "이어쓰기"(문서 끝) 힌트 버튼이 단축키 표기와 함께 표시된다.
- **When** 사용자가 힌트 버튼을 클릭하거나 Mod+Enter를 누르면
- **Then** 이 시점에 처음으로 AI 요청이 발생하고, 문서 문체·종결어미를 상속한 초안이 회색 고스트 텍스트로 스트리밍되며 [✓ 넣기]·[✕ 지우기]·[■ 중지]가 항상 표시된다.

### AC-AI-014: 확정/취소 + Tab 비확정 (REQ-AI-030, 031) [edge]

- **Given** 고스트 텍스트가 활성인 상태에서
- **When** 사용자가 [✓ 넣기]를 클릭하거나 Mod+Enter를 재입력하면
- **Then** 고스트가 실제 텍스트로 확정되고(단일 트랜잭션, Mod+Z 복원 가능).
- **When** 대신 Tab 키를 누르면
- **Then** Tab은 기존 들여쓰기(`indentWithTab`)로 동작하고 고스트는 소멸한다(통짜 삽입 없음).
- **And** [✕ 지우기]·Esc 또는 사용자 타이핑 시에도 고스트가 소멸한다.

## 모듈 5 — 오류·무손상 원칙

### AC-AI-015: 적용 재검증 + 스트리밍 중 원문 편집 (REQ-AI-035, 036) [edge]

- **Given** 제안 카드가 생성된 뒤 원문 앞쪽 편집으로 대상 범위 텍스트가 바뀐 상태에서
- **When** 사용자가 [✓ 바꾸기]를 클릭하면
- **Then** dispatch 직전 재검증에서 불일치가 감지되어 적용이 중단되고 "원문이 바뀌어 적용할 수 없어요" 카드가 표시된다(문서 무변경).
- **And** 스트리밍 중 사용자가 대상 원문 범위를 편집하면 무통보 취소 대신 "원문이 편집되어 이 제안을 멈췄어요 [무시] [다시 요청]" 배너가 표시된다(범위 밖 편집은 요청에 영향 없음).

### AC-AI-016: 로그인 만료 (REQ-AI-037) [edge]

- **Given** AI 사용 중 CLI 로그인이 만료될 때
- **When** 요청이 실패하면
- **Then** 원문을 손상시키지 않고 "로그인이 풀렸어요 [연결 안내 보기]" 카드로 온보딩 모달을 재사용하며, stderr 분류로 로그인 만료 / 네트워크 차단 / 기타를 구분해 네트워크 오류를 로그인 만료로 오안내하지 않는다.

### AC-AI-017: 빈 제안 + Mod+S 독립 (REQ-AI-038, 039) [edge]

- **Given** 이미 자연스러운 문장을 선택해 편집을 요청할 때
- **When** 제안 결과가 빈 문자열이거나 원문과 동일하면
- **Then** "바꿀 곳이 없어요" 카드가 표시되고 빈 교체가 수행되지 않는다.
- **And** 스트리밍 진행 중 사용자가 Mod+S로 저장하면 저장은 AI 요청과 독립적으로 처리되고 진행 중 요청이 유지된다(습관성 저장이 결과를 날리지 않음).

### AC-AI-018: 파싱 실패 raw 미노출 + 무통보 취소 금지 (REQ-AI-040, 033, 034) [edge]

- **Given** CLI 버전업 등으로 스트림 파싱이 실패할 때
- **When** 최종 `result` 필드 2차 파싱마저 실패하면
- **Then** raw JSON을 카드에 노출하지 않고 "도구 업데이트로 문제가 생겼어요" 오류 카드를 표시한다.
- **And** 어떤 AI 요청·제안 카드가 사라질 때도 반드시 이유를 명시한 배너/카드로 알리며(무통보 자동 취소 없음), 어떤 실패에서도 문서가 변경되지 않는다.

### AC-AI-019: 자동 트리거 없음 (REQ-AI-032)

- **Given** 사용자가 타이핑 중이거나 커서가 이동할 때
- **When** 별도의 버튼 클릭·단축키 입력이 없으면
- **Then** 어떤 AI 요청(CLI 스폰·토큰 소모)도 발생하지 않는다(키 입력마다 호출하는 커서급 자동완성 없음).

### AC-AI-020: 테마 토큰 (REQ-AI-010)

- **Given** AI 카드·툴바·모달·고스트·배너 관련 신규 CSS가 적용된 상태에서
- **When** CSS를 검사하면
