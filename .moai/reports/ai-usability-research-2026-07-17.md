# mdedit AI 사용성 리서치 — 2026-07-17

평가 기준: mdedit AI는 "글 쓰는 사람 옆에서 가볍게 거드는 인에디터 어시스턴트"다. Notion AI / Cursor 급 야심이 아니라, 빠르고 작은 도움이 척도다. 과설계된 제안은 오히려 마이너스로 본다.

조사 방법: SPEC(AI-001/002/003/005), Rust 프롬프트·스폰 계층(`src-tauri/src/ai/*`), 프론트 확장 3종(선택 툴바·제안 카드·고스트 텍스트), IPC/릴레이/스토어 정적 분석 + 오너 도그푸딩 노트 2건(`이어쓰기-테스트.md`, `프롬프트-핫픽스-테스트.md`) 대조. 실제로 모델에 나가는 프롬프트 문자열까지 추적했다.

## 요약 (5줄)

1. 뼈대는 견고하다: 프롬프트 조립이 전부 Rust(단일 소스)이고, 컨텍스트 절단·문단 경계·mermaid 펜스·이어쓰기 반복금지 등 최근 핫픽스가 프롬프트/테스트에 잘 박혀 있다.
2. 그러나 **인라인 변환(다듬기/개요/표/짧게) 시스템 프롬프트가 "[대상]만 변환하라"를 명시하지 않아**, 앞뒤 문맥이 풍부한 문서 한가운데서 다른 섹션 내용이 결과에 섞이는 "흡수(absorption)" 위험이 남아 있다 — 오너의 A-1/A-2 실패 시나리오와 정확히 일치.
3. **첫 토큰 지연**이 최대 리스크: 요청마다 `claude -p` 프로세스를 새로 스폰하는데 워치독/타임아웃이 없어, 네트워크 지연 시 스켈레톤이 무한정 돌 수 있다(가진 건 [취소]뿐).
4. `truncated`(문서 길어 일부만 참고) 고지가 **실질적으로 죽은 코드**다 — 카드 완료 경로가 플래그를 넘기지 않고, 고스트는 아예 표시 수단이 없다. P7 "침묵 절단 금지"가 조용히 깨져 있다.
5. 고스트 이어쓰기 UX는 카드보다 빈약(재요청·길이옵션·절단고지 없음). 알려진 후속(프롬프트 핫픽스·길이옵션·고스트 재요청)은 대체로 타당, "히스토리"는 포지셔닝 이탈이라 기각 권장.

## 기능 지도 (표면 × 트리거 → 컨텍스트 → 출력 → 사용자 조작)

|---|---|---|---|---|---|

배제 게이트(자유 이어쓰기): 코드펜스·표 내부=완전 배제, 리스트·인용=수동 트리거는 허용하되 힌트만 배제. 모델 기본 haiku, "고급 모델" 토글 시 sonnet. 동시 요청 1개(새 요청이 이전 in-flight를 취소 통보 후 교체).

오류 분류(Rust `classify_stderr`): login / network / other(+parse). 카드는 login이면 "연결 안내 보기", network/other면 "다시 시도" 노출. raw stderr는 프론트로 안 나감.

## 사용 케이스 시뮬레이션

### (a) 기술 블로그 초안 이어쓰기 — 문단 중간
- 시나리오: `이어쓰기-테스트.md §1`처럼 "…특히 에티오피아 예가체프는" 뒤에 커서, Mod+Enter.
- 실제 동작 추적: `getFreeContinueContext` 자격 성립 → `[문서 개요]`(# 커피의 세계 + 소제목들) + `[직전 본문]`(앞 전체, 1500자 절단) + `[뒤 문맥]`(다음 문단들). 시스템 프롬프트가 "끊긴 문장부터 완성, 뒤 문맥 반복 금지" 지시. haiku가 "예가체프는 …" 뒤를 이어 회색 고스트로 스트리밍.
- 도움 정도: ★★★★☆ — 핵심 유스케이스, 트리거·프롬프트·반복금지 지시가 잘 맞물린다.
- 걸림돌: 첫 토큰까지 프로세스 콜드스타트 지연. 길이 제어 없어 haiku가 한두 문단을 통으로 뽑아버리면 "가볍게 한 줄 거들기" 기대와 어긋날 수 있다.

### (b) 회의록을 요점 정리로 다듬기 — 인라인 [개요로 정리]
- 시나리오: `프롬프트-핫픽스-테스트.md A-2` — "4. 태그 분류 규칙" 본문 한 문단만 선택 → ✨ → 개요로 정리.
- 실제 동작 추적: `[앞 문맥]`(3. 인증 흐름 문단) + `[대상]`(4번 문단) + `[뒤 문맥]`(5번 액션 아이템). 시스템 프롬프트 = "주어진 텍스트를 개괄식 불레틴으로 정리". **"[대상]만"이라는 스코핑이 없다.** haiku가 [앞/뒤 문맥]까지 "주어진 텍스트"로 오해하면 문서 전체를 개요화 → 오너가 정의한 ❌ 실패("개요/아키텍처/인증 등 전체가 개요화됨").
- 도움 정도: ★★★☆☆ (프롬프트 흡수 리스크로 감점)
- 걸림돌: **[High] 인라인 변환 프롬프트의 대상 스코핑 부재**. 카드 라벨은 [앞/대상/뒤]로 나뉘지만 시스템 프롬프트가 이를 강제하지 않는다.

### (c) README 섹션 채우기 — 빈 헤딩
- 시나리오: `## 설치` 헤딩 밑 빈 줄에서 힌트/Mod+Enter.
- 실제 동작 추적: `getSectionFillContext` 성립 → `[문서 개요]`(전체 헤딩) + `[직전 본문]`(앞 1500자). "문체·종결어미 상속" 프롬프트. 고스트로 초안 스트리밍.
- 도움 정도: ★★★★☆ — 개요 상속이 톤 유지에 효과적. README처럼 헤딩 구조가 뚜렷하면 특히 잘 맞는다.
- 걸림돌: 개요(헤딩 목록)가 Rust에서 **무절단**이라, 헤딩 수백 개짜리 문서에선 개요만으로 컨텍스트가 불필요하게 커진다(비용/지연). README 규모에선 무해.

### (d) 문장 톤 다듬기 — 인라인 [다듬기]
- 시나리오: 이미 깔끔한 문장 선택 → 다듬기(회귀 R-1: 과교정 금지).
- 실제 동작 추적: 시스템 프롬프트 = **"너는 한국어 문장 교정기다…의미·정보 유지"**. 깨끗한 문장이면 거의 그대로 나와야 정상. `isEmptyOrIdentical`이 원문과(공백무시) 동일하면 카드가 'empty'로 빠져 헛교체를 막는다(좋은 방어).
- 도움 정도: ★★★★☆ (순수 한국어), ★★☆☆☆ (영어/혼용 시)
- 걸림돌: **다듬기 프롬프트가 "한국어 문장 교정기"로 하드코딩**. 영어/혼용 문단을 다듬으면 언어 편향 지시가 나간다(케이스 g와 연결).

### (e) 표/목록 중간에서 이어쓰기
- 시나리오: `이어쓰기-테스트.md §4/§5` — 표 셀 안 vs 리스트 항목 안에서 Mod+Enter.
- 실제 동작 추적: `getContinueBlockGate` — 표(Table)/코드펜스 내부는 `blocked=true` → 트리거 자체 무반응(토큰 0). 리스트/인용은 `hintExcluded`만 true → 힌트는 안 뜨지만 수동 Mod+Enter는 허용. `프롬프트-핫픽스-테스트.md B-1`처럼 리스트 마지막 "…담당은" 뒤에서 이어쓰면 뒤 문맥 없음 → 문서끝 분기와 동일, "담당은"을 다시 포함하지 않고 뒤 어절만 이어야 통과.
- 도움 정도: ★★★★☆ — 구문 게이트 설계가 깔끔하다.
- 걸림돌: 리스트 항목 이어쓰기에서 haiku가 앞 어절을 재복창할 리스크(B-1 ❌). 반복금지 지시는 "뒤 문맥"에만 걸려 있고, "직전 본문의 끝 어절을 반복하지 말라"는 명시는 약하다.

### (f) 긴 문서(수천 줄) 중간 편집
- 시나리오: 3000줄·헤딩 200개 문서 중간에서 자유 이어쓰기.
- 실제 동작 추적: 프론트가 `contextBefore=slice(0,pos)`, `contextAfter=slice(pos)` **문서 통째**를 IPC로 전달(앞/뒤 각각 Rust에서 1500자 절단). 그러나 `outline`은 **200개 헤딩 전부**를 join해 보내고 Rust `build_continue_prompt`가 개요를 **절단하지 않는다**.
- 도움 정도: ★★★☆☆
- 걸림돌: **[Med] 개요 무절단** → 긴 문서에서 프롬프트가 헤딩 목록으로 비대해져 haiku 컨텍스트/비용 낭비, 근처 문맥의 신호가 희석. IPC로 매 요청 수 MB 문자열 전달도 비효율(절단은 Rust라 앞/뒤는 방어되지만 outline은 구멍).

### (g) 한국어/영어 혼용 문서
- 시나리오: 영어 단락 다듬기, 혼용 문서 이어쓰기.
- 실제 동작 추적: 다듬기="한국어 문장 교정기"(편향), 나머지 프롬프트도 전부 한국어로만 작성 → 모델이 한국어로 응답하려는 관성. 이어쓰기 "종결어미 상속"은 한국어 문법 전제.
- 도움 정도: ★★☆☆☆
- 걸림돌: **[Med] 프롬프트 언어 편향**. "입력 언어를 그대로 따르라" 한 줄이 없다. 영어 문서에서 한국어 결과가 섞여 나올 수 있다.

### (h) 아주 짧은 메모에서 힌트 알약
- 시나리오: "우유 사기" 3어절 메모, 커서 줄 끝에서 3초 유휴.
- 실제 동작 추적: `isFreeContinueHintEligible` = 줄끝 + 미종결 + 배제노드 밖 → 조건 충족 → "✨ 이어쓰기 ⌘⏎" 알약 노출. 트리거 시 개요 없음(헤딩 0), 직전 본문 극소 → haiku가 근거 없이 일반적 문장 채움.
- 도움 정도: ★★☆☆☆
- 걸림돌: **[Low] 저맥락 힌트 스팸**. 문맥이 거의 없는 메모에서 이어쓰기를 권해도 결과는 뻔한 필러. 힌트 자격에 "최소 문맥/개요 존재" 조건이 없다. 방해 비용은 낮지만(3초 후 작은 알약, 클릭 안 하면 사라짐) 신뢰를 깎는다.

### (참고) 다이어그램 변환 — 핫픽스 검증
- `프롬프트-핫픽스-테스트.md C-1` 대응: 프롬프트가 이제 "```mermaid 펜스·설명 없이 코드만" 명시(BUG-3b 수정), 카드가 `stripMermaidFence`로 벗겨 사전검증→미니렌더, 삽입 시 `ensureMermaidFence`로 되씌움, 1회 실패시 오류동봉 자동재요청, 2회+면 "목록으로" 폴백(무한루프 방지 플래그까지). **핫픽스가 코드로 확인됨.** 잔존: 컨텍스트 노드까지 그리는 흡수는 (b)와 동일 뿌리.

## 사용성 평가표

| 항목 | 점수 | 근거 |
|---|---|---|
| 발견성(Discoverability) | ★★★★☆ | 선택하면 ✨가 즉시 보임(강). 이어쓰기/섹션채우기는 3초 힌트 알약 + 단축키 표기로 학습 가능. 다만 Mod+Enter를 힌트 없이 아는 유저는 드물고, 표/코드펜스 무반응은 "왜 안 되지" 혼란 가능. |
| 방해 비용(Interruption) | ★★★★☆ | 힌트는 3초 유휴 후에만, 작은 알약, 문서변경·이동 시 즉시 사라짐. 자유위치 힌트는 보수 조건(미종결 줄끝)이라 스팸 억제 양호. 케이스(h) 저맥락 노출만 옥에 티. |
| 신뢰·통제(Trust/Control) | ★★★★☆ | 원문은 확정 전 절대 안 바뀜(카드는 흐리게, 고스트는 뷰 전용), 확정은 단일 트랜잭션(Mod+Z 1회 복원), 적용 직전 원문 재검증(stale 방어), 표/다이어그램·2K~4K는 삽입 전용으로 파괴 차단. 매우 견고. 감점: `truncated` 고지가 죽어 있어 "일부만 참고"를 유저가 모른다. |
| 지연 체감(Latency) | ★★☆☆☆ | 스켈레톤 + "✨ 작성 중…" 펄스 + ✨ 버튼 펄스로 "일하는 중" 신호는 있음. 그러나 요청마다 CLI 콜드 스폰 + 워치독/타임아웃 부재 → 네트워크 지연 시 무한 스켈레톤, 탈출구는 [취소]뿐. 가장 약한 축. |
| 실패 상태(Failure) | ★★★★☆ | stderr를 login/network/other로 분류, 안전 메시지만 노출, login이면 "연결 안내 보기"로 온보딩 연결. 빈/동일 응답은 'empty'로 처리. 감점: "응답은 왔는데 result 미추출"=parse지만 무한 대기(스트림 델타만 오고 result 라인 없음) 방어는 릴레이 종료 판정 의존 — 프로세스가 안 죽으면 종료 판정도 안 옴. |

## 수정 필요 목록 (우선순위)

### High
1. **인라인 변환 프롬프트의 대상 스코핑 부재 → 컨텍스트 흡수** (`prompt.rs` `AiFeature::system_prompt`)
   - 증상: [앞/뒤 문맥]까지 변환해 다른 섹션이 결과에 섞임(오너 A-1/A-2 ❌ 시나리오).
   - 수정: 인라인 계열(polish/outline/table/diagram/shorten/custom) 시스템 프롬프트에 "오직 `[대상]` 텍스트만 변환·정리하고, `[앞 문맥]`/`[뒤 문맥]`은 이해를 돕는 참고 자료일 뿐 결과에 포함하지 말라"를 명시. `COMMON_INSTRUCTION`에 얹거나 `build_inline_prompt` 전용 지시로 추가. haiku엔 특히 중요.
2. **요청 워치독/타임아웃 부재 → 무한 스켈레톤** (`mod.rs` 릴레이 / 프론트 카드·고스트)
   - 증상: 네트워크 지연·CLI 행 시 스켈레톤이 영원히, 탈출구 [취소]뿐.
   - 수정: 프론트에 소프트 워치독(예: N초 무응답 시 카드/고스트에 "아직 준비 중이에요, 취소할 수 있어요" 보조 문구) + Rust에 하드 타임아웃(자식 kill → ai://error 'network'/'other'). 프론트 전용 문구만이라도 즉시 가능(S).

### Medium
3. **`truncated` 고지 죽은 코드 (P7 침묵 절단 금지 위반)** (`ai-suggestion-card.ts:1059`, 고스트 전반)
   - 증상: `controller.onComplete(s.streamBuffer)`가 `s.truncated`를 안 넘겨 카드 "문서가 길어 일부만 참고했어요"가 절대 안 뜸. 고스트엔 표시 수단 자체가 없음.
   - 수정: 카드는 `onComplete(s.streamBuffer, { truncated: s.truncated })`로 1줄 수정. 고스트는 done 시 절단이면 컨트롤 옆 작은 노트 추가(S).
4. **개요(헤딩 목록) 무절단** (`prompt.rs` `build_section_prompt`/`build_continue_prompt`)
   - 증상: 헤딩 많은 긴 문서에서 outline이 프롬프트를 비대화(비용/신호 희석), IPC로도 통째 전달.
   - 수정: outline에 상한(예: 최근/근처 헤딩 우선 N개 or M자) + 초과 시 truncated 플래그. 근처 헤딩 우선이 이상적.
5. **프롬프트 언어 편향** (`prompt.rs` polish 및 공통)
   - 증상: 다듬기="한국어 문장 교정기", 전반적 한국어 전제 → 영어/혼용 문서 오작동.
   - 수정: polish를 "주어진 텍스트의 언어를 유지한 채 맞춤법·문장을 다듬어라"로 일반화, `COMMON_INSTRUCTION`에 "입력 텍스트의 언어를 그대로 따르라" 추가.
6. **고스트 이어쓰기 UX 빈약** (재요청·길이·절단고지 없음) — 마이너 기능 제안 1·2와 연결.

### Low
7. **저맥락 힌트 노출** (`isFreeContinueHintEligible`): 개요/직전 본문이 사실상 없을 때 힌트 억제 조건 추가.
8. **리스트 이어쓰기 앞어절 재복창**(B-1 ❌ 잔존 가능): 반복금지 지시를 "직전 본문의 마지막 어절/구를 반복하지 말라"까지 확장(뒤 문맥 없을 때도 적용).

## 마이너 기능 제안

각 항목: 가치 가설 / 노력(S·M) / 만들지 말 것.

### 채택 권장
1. **고스트 이어쓰기 재요청(↻ 다른 버전)** — 가치: 이어쓰기가 마음에 안 들면 재타이핑 없이 한 번 더. 카드의 `fireReRequest`/`onReRequest` 패턴을 고스트 컨트롤에 재사용. **S**, 프론트 전용. / 만들지 말 것: 재요청 히스토리 스택·버전 비교 UI.
2. **이어쓰기 길이 옵션(짧게 / 보통)** — 가치: haiku가 문단을 통으로 뽑는 문제 완화, "한 줄 거들기" 기대와 정렬. 고스트 컨트롤에 토글 하나 → continue 시스템 프롬프트에 "한두 문장만"/"한 문단까지" 지시 추가. **S**, 프론트+프롬프트 1줄. / 만들지 말 것: 슬라이더·문자수 정밀 지정.
3. **요청 지연 워치독 문구** (수정#2의 프론트 절반) — 가치: 무한 스켈레톤 공포 제거. N초 후 카드/고스트에 "아직 준비 중… 취소 가능" 보조 문구. **S**, 프론트 전용. / 만들지 말 것: 진행률 바(스트림이라 %가 없음, 가짜 진행률 금지).
4. **`truncated` 고지 살리기** (실질 버그픽스) — 가치: P7 신뢰 회복. **S**. / 만들지 말 것: 절단 상세 뷰어.

### 보류
5. **다후보 제안 랭킹** — 여러 후보 생성 후 고르기. 비용·지연 배수 + 선택 피로. 라이트 포지셔닝과 상충. 리텐션 데이터로 "재요청 빈도 높음"이 확인되면 그때 재검토. **M**.
6. **인라인 커스텀 지시 프리셋 저장**("영어로 번역" 등 자주 쓰는 것 저장) — 편의는 있으나 영속 상태 도입. 수요 확인 후. **M**.

### 기각 (포지셔닝 이탈)
- **채팅 패널 / 멀티턴 에이전트** — 명시적 아웃오브스코프(M4급). 인에디터 어시스턴트 정체성과 정면 충돌.
- **영속 히스토리 패널** — 상태 인프라·별도 표면. 라이트 어시스턴트가 아니라 도구가 됨. (최대치로 허용한다면 "직전 제안 다시 넣기" 세션 한정 정도, 그 이상은 X.)
- **문서 전체 요약/자동 목차/전체 리라이트** — 대상이 "선택/커서 주변"이 아니라 문서 전체가 되는 순간 무거워지고 흡수 문제도 폭발. 명시적 비대상.
- **인라인 자동 트리거(타이핑 중 자동 제안)** — REQ-AI-032(토큰 0 로컬 판정) 원칙·방해 비용과 충돌. 커서급 자동 요청 금지 계약도 이미 존재.

## 결론

mdedit AI는 "가벼운 인에디터 어시스턴트"라는 자기 규정에 대체로 충실하며, 특히 **무손상 보장(확정 전 원문 불변·단일 트랜잭션·재검증)과 최근 프롬프트 핫픽스(다이어그램 펜스·이어쓰기 반복금지)** 는 완성도가 높다. 남은 핵심은 세 가지다: (1) **인라인 변환의 대상 스코핑**을 프롬프트에 명시해 흡수를 막을 것(오너가 직접 짚은 실패), (2) **지연 워치독**으로 무한 스켈레톤을 닫을 것, (3) **truncated 고지·개요 절단·언어 편향** 같은 침묵/편향을 정리할 것. 이 셋은 전부 프롬프트 문자열 또는 프론트 1~2줄 규모로, 새 인프라 없이 포지셔닝을 지키며 체감을 크게 올린다. 신규 기능은 고스트 재요청·길이 옵션 정도의 "작게 거드는" 선에서 멈추는 것이 이 제품의 미덕과 맞다.
