주요 결과 (판정에 참고할 점)

아래는 이번 실행에서 관찰·측정한 사실입니다. 관찰 없이 추론한 부분은 (추정)으로 표시했습니다. 수치의 원본은 evidence/*.json입니다.

  1. 렌더 성공·거부: 유효 샘플 19개(프리셋 7종, stateDiagram-v2, mindmap, pie title, classDef·style 포함)가 jsdom·webkit 두 환경 모두 PeleError 없이 렌더됐습니다. AI 모의 1차 응답 notarealdiagramtype foo!!!는 PeleError code: "unsupported-diagram"(line 0, column 0)으로 거부됐습니다. 실제 AI 응답 샘플은 미수집입니다.
  2. 배치 차이 — 눈으로 볼 곳:
    • 03-subgraph-C-horizontal: mermaid는 서브그래프 안 노드를 가로(파싱→AST)로 놓고, pele는 소스대로 세로(TB)로 놓습니다. 두 서브그래프 제목은 pele에서도 한 줄이고 상자는 겹치지 않습니다.
    • 15-mindmap-deep·10-preset-mindmap: mermaid는 방사형·채색 노드, pele는 좌우로 펼친 트리와 계열색 선으로 모양이 크게 다릅니다.
    • 14-state-v2-composite: mermaid는 노트를 아래쪽에, pele는 게시 옆에 둡니다. 전체적으로 pele 출력이 더 작고 촘촘합니다(예: 01번 mermaid 대비 노드 간격이 좁음).
    • 06-preset-gantt: mermaid는 폭 전체로 늘어나 글자가 아주 작아지고, pele는 날짜 눈금이 읽힐 크기를 유지합니다.
    • 20-image-node: mermaid는 앱 CSP 아래에서 Loading error.로 실패합니다. pele는 images: false로 이미지 없이 라벨과 화살표만 그립니다(이미지 자리 빈 공간이 남음).
  3. F1 수식 라벨(측정만): 지금 앱과 같은 mermaid strict 설정은 webkit에서 $$x^2 + y^2$$를 KaTeX(foreignObject 안 MathML)로 수식으로 표시했습니다(img/18-math-label-mermaid.png). pele는 math 해석기를 주지 않으면 foreignObject를 만들지 않고 $$…$$ 원문을 일반 글자로 보입니다(img/18-math-label-pele.png). design.md D15는 "foreignObject라서 정화기가 지운다"고 적었지만 실제 1.10.0 기본 출력에는 foreignObject가 없습니다. 교체하면 다이어그램 안 수식은 원문 TeX로 보이게 됩니다. 실제 앱 미리보기에서의 표시는 MANUAL 항목입니다.
  4. F2 내보내기 색: 값을 풀어 넣은(literal) HTML·DOCX는 var(--pele- 0건이고 색이 남습니다. 풀어 넣지 않은(as-is) 결과는 라이트·다크 모두 pele 라이트 대체값으로 그려져, 다크 HTML에서 파이 제목·범례 글자가 어두운 배경에 거의 안 보입니다(exports/html-dark-as-is.png).
  5. F3 다크 내보내기의 대비 문제: DOCX 페이지는 항상 흰색인데(exportDocx.ts는 테마를 쓰지 않음), 다크 literal PNG는 배경이 투명하고 글자가 밝은색이라 시퀀스 메시지·파이 제목·범례가 흰 페이지에서 거의 안 보입니다(exports/docx-dark-literal.docx.png). 또 classDef cool fill:#9cf처럼 채우기만 정하고 글자색을 정하지 않은 노드는 다크에서 밝은 글자 + 밝은 채우기가 됩니다(pele 이슈 #29와 같은 현상). 같은 현상이 mermaid dark에도 있습니다(13-classdef-style 다크 칸).
  6. F4 글꼴과 측정: pele는 fontFamily 옵션(기본 sans-serif)으로 글자 폭을 재고, 화면에는 --pele-font로 그립니다(dist/types.d.ts RenderOptions.fontFamily). --pele-font를 앱 글꼴(Barlow)에 연결하면서 fontFamily를 같이 넘기지 않으면 측정 폭과 표시 폭이 달라질 수 있습니다 (추정, 이번에 측정하지 않음). 그래서 이 보고서는 글꼴 변수를 연결하지 않았습니다.
  7. F5 오류 위치: 샘플 변형 6,264개를 렌더해 본 결과 pele 오류 위치는 line≥1·column≥1(syntax) 또는 line 0·column 0(unsupported-diagram, semantic, 일부 syntax) 두 가지뿐이었고, line≥1·column 0은 한 번도 나오지 않았습니다. AC-PREVIEW015-007의 가운데 경우 (L행)에 맞는 소스를 M1에서 찾지 못했습니다(존재하지 않는다고 단정하지는 않음).
  8. F6 정화 후 모양: webkit에서 정화 전·후 픽셀이 19개 샘플 모두 같았습니다. 인라인 style 개수와 var(--pele- 개수는 그대로이고, pele 출력에는 <style>와 id가 원래 없습니다. 정화기가 루트의 role="graphics-document document" 속성은 지웁니다(aria-roledescription은 남음).
  9. F7 maxWidth는 배치를 바꿈: autoDirection: false에서도 maxWidth를 넘기면 간격이 줄어듭니다(03번 767×316 → 715×284, 방향은 TB 그대로). 고정 옵션에 maxWidth가 없으므로 모듈 출력은 칸 폭과 무관하게 같습니다. 대조로 autoDirection: true + maxWidth: 560은 15번 마인드맵을 575×188 → 186×452로 바꿨습니다.
  10. F8 측정기에 따른 크기 차이: 같은 입력이라도 jsdom(내장 글자 폭 표)과 webkit(캔버스)의 결과 크기가 다릅니다(예: 01번 369×409 vs 342×401). D14대로 unit/은 바이트 비교, browser/는 구조 확인에만 써야 합니다.
  11. F9 pele 내부 변수: pele는 루트 style에 --_bg:var(--pele-bg,#fff) 같은 내부 변수를 두고 요소는 var(--_bg)를 씁니다. literal 치환 뒤에도 var(--_…)는 남지만 SVG 안에서 정의되므로 data URI 래스터에서도 색이 나옵니다. AC-020의 "0건" 확인은 var(--pele- 문자열에만 걸어야 합니다.
  12. F10 responsive: true는 루트 style에 max-width:100%;height:auto를 넣어 560px 칸에서 넓은 다이어그램(03번 767px, 06번 800px, 15번 575px)을 줄여 보입니다. false는 그 두 속성만 빠지고 자연 크기로 그려져 560px 칸에서 가로 스크롤이 생깁니다. 레이아웃·크기 값은 두 값에서 같았습니다(19개 샘플).
  13. 시간: 다이어그램 32개 문서에서 mermaid 507–579ms, pele 32–34ms(3회, 레이아웃 포함 시 각각 512–585ms, 34–36ms). 다이어그램 1개 콜드 렌더는 mermaid 23–47ms, pele 3–4ms.
